# รีวิว UI Studio 0.3 และ accessibility รอบใหม่

รีวิวนี้เป็นงาน Claude D ใน `docs/CLAUDE_NEXT_TASKS.md` อ้างอิงโค้ด `v0.3-studio` commit `d9556ec` เอกสารเดิม `docs/claude/UI_REVIEW.md` ยังเก็บ snapshot ของรุ่น 0.2 ไว้ตามเดิม เลขบรรทัดในเอกสารนี้อ้างอิง `d9556ec`

## วิธีตรวจและหลักฐาน

ผมใช้สองวิธี วิธีแรกคืออ่านซอร์สของ `CameraActivity`, `StudioUi`, `StudioSettings`, `ManualControls`, `VideoActivity`, `SpecialVideoActivity`, `RawLabActivity`, `DocumentActivity`, `ClipEditorActivity`, `GalleryActivity` และหน้าคลัง (`StudioLibraryActivity` ใน `MediaLedger.kt`) วิธีที่สองคือเทสต์อัตโนมัติ `app/src/androidTest/java/th/ogay/luma/StudioAccessibilityTest.kt` ที่เปิดแต่ละหน้าจอจริงบน emulator แล้วไล่ view tree เพื่อหาสี่เรื่อง ได้แก่ ปุ่มที่เล็กกว่า 48 dp, ปุ่มที่ไม่มีชื่อ, ข้อความที่ถูกกล่องตัด และปุ่มที่ล้นออกนอกจอ เทสต์ตรวจทุกหน้าที่ฟอนต์ 1.0 และ 2.0 และตรวจหน้ากล้องกับหน้าวิดีโอในแนวนอนด้วย หลังจบ เทสต์คืนค่าฟอนต์และการหมุนจอเสมอ

ผลที่อ้างในเอกสารนี้มาจาก GitHub Actions [run 42559434191](https://github.com/BunnyBubui/luma-camera/actions/runs/42559434191) บน emulator Android 11 (API 30) จอ 320×640 px ความหนาแน่น 1.0 หรือกว้าง 320 dp ซึ่งแคบกว่า Reno15 ดังนั้นปัญหาที่พบบนจอนี้อาจไม่เกิดบนจอที่กว้างกว่า แต่ปัญหาข้อความถูกตัดที่ฟอนต์ 2.0 ส่วนใหญ่มาจากความสูงที่ตั้งตายตัว จึงไม่ขึ้นกับความกว้างจอ

ข้อจำกัดของหลักฐาน: การที่ view มี accessibility node ไม่ได้แปลว่าผ่านการฟัง TalkBack จริง และการอ่านซอร์สไม่ใช่การวัดความลื่นที่ 60/120 Hz ทั้งสองเรื่องยังต้องทดสอบบนเครื่องจริงตาม F06 และหัวข้อ 5 ใน `RENO15_TEST_PROTOCOL.md`

## สรุปผลจากเทสต์อัตโนมัติ

เทสต์พบปัญหา 51 รายการ ที่ฟอนต์ 1.0 พบ 11 รายการ และที่ฟอนต์ 2.0 พบ 40 รายการ (ไม่นับรายการที่หาปุ่ม "เพิ่มเติม" ไม่เจอ ซึ่งอธิบายใต้ตาราง)

| หน้าจอ | ฟอนต์ 1.0 | ฟอนต์ 2.0 | ปัญหาหลัก |
|---|---|---|---|
| กล้อง (แนวตั้ง) | 2 | 4 | ปุ่ม "AI" กว้าง 41 dp, รูปย่อ 44×44 dp, ปุ่มซูมถูกตัด, ปุ่มเมนูล้นจอ |
| กล้อง (แนวนอน) | 5 | 6 | ปุ่มอัลบั้มและปุ่มสลับกล้องเห็นแค่ 28 จาก 52 px |
| วิดีโอ | 1 (แนวนอน) | 3 | ปุ่ม "คลังวิดีโอ / แต่งคลิป" ล้นจอในแนวนอน, ปุ่มซูม A→B และคันโยกถูกตัด |
| Slow motion | 0 | 2 | หัวข้อและข้อความแจ้งถูกตัด |
| RAW Lab | 0 | 4 | หัวข้อ คำอธิบาย และปุ่มถูกตัด |
| เอกสาร | 0 | 8 | ทุกปุ่มในแถวล่างและหัวข้อถูกตัด |
| แต่งคลิป | 2 | 8 | Spinner ไม่มีชื่อ, ปุ่ม codec ล้น |
| รูปถ่าย (Gallery) | 1 | 2 | ปุ่มย้อนกลับ 46 dp, ปุ่ม "รูปทั้งหมด" ล้นจอ |
| คลัง | 0 | 3 | หัวข้อและคำอธิบายถูกตัด |

แผงล่าง "เพิ่มเติม": รอบที่เก็บผลนี้ เทสต์หาปุ่ม "โหมด เพิ่มเติม" ไม่เจอ เพราะที่ฟอนต์ 2.0 ปุ่มนี้อยู่นอกจอในแถบโหมดที่เลื่อนแนวนอน ผมแก้เทสต์ให้เลื่อนแถบก่อนแล้ว จึงยังไม่มีผลว่าแผงนี้เลื่อนถึงปุ่มสุดท้ายได้หรือไม่

## ข้อค้นพบ

### สูง

**1. หมุนจอระหว่างอัดวิดีโอทำให้คลิปหยุด** — `VideoActivity` ไม่ได้ประกาศ `configChanges` ใน manifest (`AndroidManifest.xml:17`) เมื่อหมุนจอ ระบบจึงสร้าง Activity ใหม่ และ `onPause()` เรียก `recording?.stop()` (`VideoActivity.kt:184`) ผลที่คาดคือคลิปอัดต่อ หรือหน้าจอล็อกแนวไว้ระหว่างอัด แต่ผลที่ได้จากซอร์สคือคลิปจบทันทีที่หมุน วิธีทำซ้ำคือเริ่มอัดในแนวตั้งแล้วหมุนเป็นแนวนอน ข้อนี้มาจากการอ่านซอร์ส ยังไม่ได้ทำซ้ำบนเครื่อง `SpecialVideoActivity` และ `RawLabActivity` ก็ไม่มี `configChanges` เช่นกัน ควรตรวจแบบเดียวกัน

**2. หน้าวิดีโอไม่มี layout แนวนอน** — หน้าวิดีโอวางทุกอย่างซ้อนกันแนวตั้งด้วยความสูงตายตัวรวม 314 dp (แถบหัว 60, แถบเครื่องมือ 52, ป้ายโหมด 42, แถบปุ่ม 112, ปุ่มคลัง 48; `VideoActivity.kt:61-83`) ในแนวนอน ภาพพรีวิวจึงเหลือพื้นที่น้อย และเทสต์พบว่าปุ่ม "คลังวิดีโอ / แต่งคลิป" เห็นแค่ 30 จาก 48 px ทั้งที่ฟอนต์ 1.0 และ 2.0

**3. ข้อความถูกตัดที่ฟอนต์ 2.0 ทุกหน้าจอ** — สาเหตุเดียวกันทุกจุดคือกล่องข้อความมีความสูงตายตัวเป็น dp ขณะที่ข้อความขยายตามฟอนต์ ตัวอย่างที่เทสต์วัดได้ เช่น ปุ่มในแถวล่างของหน้าเอกสารต้องการ 84 dp แต่มี 52 dp, ปุ่ม "H.264 / HEVC" ในหน้าแต่งคลิปต้องการ 112 dp แต่มี 48 dp, หัวข้อ "RAW LAB" ต้องการ 70 dp แต่มี 56 dp จุดที่ตั้งความสูงตายตัว ได้แก่ หัวข้อหน้า (`DocumentActivity.kt:32`, `RawLabActivity.kt:48`, `ClipEditorActivity.kt:29`, `SpecialVideoActivity.kt:37`, `MediaLedger.kt:60`), หัวข้อแผงล่าง (`StudioUi.kt:35`, 54 dp) และปุ่มที่ใส่ `LayoutParams(…, dp(48))` แทนการใช้ `minHeight` ข้อเสนอคือใช้ `WRAP_CONTENT` คู่กับ `minHeight` ซึ่ง `StudioSettings` ทำอยู่แล้วและเทสต์ไม่พบปัญหาในแผงนั้น

**4. ปุ่มล้นจอในหน้ากล้องแนวนอน** — บนจอกว้าง 320 dp ปุ่มอัลบั้ม รูปย่อ และปุ่มสลับกล้องในแถบด้านข้างเห็นแค่ 28 จาก 52 px ทั้งที่ฟอนต์ 1.0 สาเหตุคือแถบหัว (60 dp) แถบรูปแบบภาพ (52 dp) และแถบโหมด (52 dp) อยู่ด้านบนทั้งหมดในแนวนอน (`CameraActivity.kt:180, 198, 275`) จึงเหลือความสูงให้แถบด้านข้างไม่พอ

### กลาง

**5. ปุ่มที่เล็กกว่า 48 dp ยังเหลืออยู่** — Codex แก้ปุ่มหลักเป็น 48 dp แล้ว แต่เทสต์ยังพบปุ่ม "รูปแบบ AI" กว้าง 41 dp เพราะ `pill()` กำหนดแค่ `minHeight` ไม่มี `minWidth` (`Ui.kt:31`), รูปย่อขนาด 44×44 dp (`CameraActivity.kt:289`) และปุ่มย้อนกลับในหน้ารูปถ่าย 46×46 dp (`GalleryActivity.kt:56`) จากการอ่านซอร์ส ปุ่ม "ISO · S · WB · AF · EV" และ "ต่อภาพ" ในโหมด PRO/Panorama สูง 44 dp (`CameraActivity.kt:274`) แต่เทสต์ไม่เห็นปุ่มนี้เพราะทดสอบเฉพาะโหมดภาพถ่าย

**6. Spinner ในหน้าแต่งคลิปไม่มีชื่อ** — `Spinner` เลือก codec (`ClipEditorActivity.kt:33`) ไม่มี `contentDescription` TalkBack จึงอ่านแค่ค่าที่เลือก ไม่บอกว่าเป็นตัวเลือกอะไร ที่ฟอนต์ 2.0 ข้อความในตัวเลือกยังถูกตัดด้วย "…"

**7. คันโยกซูมวิดีโอเป็นปุ่มที่กดแล้วไม่ทำอะไร** — "◁ เลื่อนซูม ▷" (`VideoActivity.kt:72-75`) ทำงานด้วยการลากเท่านั้น ส่วน onClick ว่าง ผู้ใช้ TalkBack จะได้ยินว่าเป็นปุ่มแต่แตะสองครั้งแล้วไม่มีผล ซึ่งขัดกับกติกา "ไม่เสนอปุ่มที่กดแล้วทำงานไม่ได้" ไม้บรรทัดซูม (`ZoomRuler`) มี accessibility action ให้ใช้แทนได้อยู่แล้ว ข้อเสนอคือเพิ่ม action เลื่อนเข้า/ออกให้คันโยก หรือซ่อนคันโยกจาก TalkBack

**8. ป้ายสถานะหน้าวิดีโอสูงไม่พอแม้ฟอนต์ปกติ** — ป้ายสถานะสูงตายตัว 40 dp (`VideoActivity.kt:66`) แต่ข้อความผิดพลาดมีสองบรรทัด ("ชุดนี้ใช้ไม่ได้ · …\nแตะค่าด้านบนเพื่อเปลี่ยน", `VideoActivity.kt:124`) ข้อความภาษาไทยสองบรรทัดที่ 14sp ต้องการมากกว่า 40 dp จึงน่าจะถูกตัด เทสต์ไม่เห็นข้อนี้เพราะ emulator เปิดชุดวิดีโอได้และไม่ได้แสดงข้อความผิดพลาด นอกจากนี้ป้ายนี้ไม่มี live region ผู้ใช้ TalkBack จึงไม่ได้ยินว่าเริ่มหรือหยุดอัดแล้ว ยกเว้นจากชื่อปุ่มชัตเตอร์ที่เปลี่ยน

### ต่ำ

**9.** ตัวเลขบนไม้บรรทัดซูมวาดด้วย `textSize = 11 * density` (`StudioUi.kt:73`) จึงไม่ขยายตามการตั้งค่าฟอนต์ ควรใช้ `TypedValue.applyDimension(COMPLEX_UNIT_SP, 11f, …)`

**10.** ที่จับแผงล่าง "━━━━" มีชื่อ "ปัดลงเพื่อปิด" (`StudioUi.kt:25`) แต่ปิดได้ด้วยการลากเท่านั้น ผู้ใช้ TalkBack ปิดได้ด้วยปุ่มย้อนกลับของระบบ ข้อเสนอคือให้แตะที่จับแล้วปิดแผงได้ด้วย

**11.** การกดค้างที่ชัตเตอร์ (ถ่ายต่อเนื่อง) และที่รูปย่อ (เปิดคลัง) ไม่มีคำใบ้บนหน้าจอและไม่ได้ตั้งชื่อ long-click action สำหรับ TalkBack

## สิ่งที่ Codex แก้แล้วและเทสต์ยืนยัน

ปุ่มเลือก (แถบโหมดและรูปแบบภาพ) ใช้พื้นเหลือง ตัวหนา และตั้ง `isSelected` กับ `stateDescription` แล้ว (`Ui.kt:38-46`) ปุ่ม `Glyph` และ `pill` ประกาศ role เป็นปุ่ม และเทสต์ไม่พบปุ่มที่ไม่มีชื่อในหน้ากล้อง ไม้บรรทัดซูมมี range info และ scroll action (`StudioUi.kt:99-102`) แผงตั้งค่า `StudioSettings` ใช้ความสูงแบบ wrap และเทสต์ไม่พบข้อความถูกตัดในแผงนั้น

## ผลการแก้ (PR #8)

ผมรับงาน build และรวมงานแทน Codex ตามที่เจ้าของโปรเจกต์มอบหมาย และแก้ข้อ 1–11 ใน PR #8 ดังนี้ ข้อ 1 ล็อกการหมุนจอระหว่างอัดในหน้าวิดีโอ, Slow motion/Time-lapse และ RAW Lab ข้อ 2 เพิ่ม layout แนวนอนให้หน้าวิดีโอ (พรีวิวซ้าย แผงควบคุมเลื่อนได้ขวา) ข้อ 3 เปลี่ยนความสูงตายตัวเป็น `WRAP_CONTENT` + `minHeight` ทุกจุดที่เทสต์พบ และในแผงล่างทุกแผง ข้อ 4 ให้แถบหัวหน้ากล้องเลื่อนแนวนอนได้และให้คอลัมน์ด้านข้างในแนวนอนเลื่อนได้ ข้อ 5 เพิ่ม `minWidth` 48 dp ให้ `pill()` และขยายรูปย่อกับปุ่มย้อนกลับเป็น 48 dp ข้อ 6 เปลี่ยน Spinner เป็นปุ่มที่มีชื่อพร้อม dialog ข้อ 7 เพิ่ม action "ซูมเข้า/ซูมออก" ให้คันโยก ข้อ 8 ให้ป้ายสถานะขยายตามข้อความ และประกาศการเริ่ม/จบคลิปให้ TalkBack ข้อ 9 ใช้หน่วย sp กับตัวเลขบนไม้บรรทัด ข้อ 10 แตะสองครั้งที่ที่จับเพื่อปิดแผงด้วย TalkBack ได้ ข้อ 11 ตั้งชื่อ long-click action ของชัตเตอร์และรูปย่อ

หลังแก้ `StudioAccessibilityTest` ถูกเปลี่ยนเป็นเทสต์ที่ล้มเมื่อพบปัญหาใด ๆ รอบแรกหลังแก้พบเหลือ 3 จาก 51 รายการ (หน้าแต่งคลิปสองรายการ และเทสต์เปิดแผง "เพิ่มเติม" ไม่ได้) ซึ่งแก้ต่อใน commit ถัดไปของ PR เดียวกัน ผลรอบสุดท้ายดูได้จาก CI ของ PR #8

ยังต้องตรวจบนเครื่องจริง: ฟัง TalkBack ทุกหน้าจอ, ฟอนต์ 200% บนจอ Reno15, และการหมุนจอระหว่างอัดวิดีโอ
