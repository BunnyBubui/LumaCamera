## B1 คลัง Luma ใช้แกลเลอรีตามดีไซน์

ภาพที่ผู้ใช้ส่งมาแสดงหน้า "คลัง Luma" เป็นรายการไฟล์ดิบ (ชื่อไฟล์ `LUMA_VIDEO_...mp4`, ไฟล์ `.json`, ปุ่มเปิด/ส่งออก/แต่ง) ให้เปลี่ยนเป็นหน้าแกลเลอรีเดียวกับแท็บ "ถ่ายด้วย Luma" ในดีไซน์ ได้แก่ grid ภาพย่อ ไม่แสดงไฟล์ `.json` เป็นรายการ (เก็บเป็นข้อมูลของวิดีโอและเปิดได้จากหน้ารายละเอียด) และเก็บปุ่มเปรียบเทียบ AI ไว้ในที่ที่เหมาะสม คงตรรกะเดิมของ Luma shot (AI/RAW/DNG, ลองใหม่, `EnhanceWorker`, ข้อมูลภาพ)

## B2 คลังภาพทั้งหมด

หน้าทั้งเครื่องตอนนี้เป็น grid ตามภาพที่ผู้ใช้ส่ง ให้เพิ่ม **แถบอัลบั้มใหม่หนึ่งแถบ** ที่ด้านบน grid

- เลื่อนซ้ายขวาได้ แต่ละอัลบั้มเป็นการ์ดปกพร้อมชื่อกับจำนวนรูป
- มีปุ่ม "ดูเพิ่มเติม" ที่ปลายแถบ แตะแล้วเปิดหน้ารวมทุกอัลบั้ม
- แตะการ์ดแล้วกรองตามอัลบั้มนั้น และแตะซ้ำเพื่อกลับไปทั้งหมด
- ปัญหาที่ผู้ใช้เจอและต้องแก้ด้วย: บางภาพหาย, แถบเมนูบนมองไม่เห็น, หน้าดูภาพเห็นแค่ภาพล่าสุดและไม่มีปุ่มไปรูปทั้งหมด รายละเอียดของแต่ละข้ออยู่ใน `CLAUDE_B_GALLERY_TASK.md`
- หมวด "ทั้งหมด / รูปภาพ / วิดีโอ / Camera / Screenshots" ที่มีอยู่ให้คงไว้ และเลื่อนไปมาได้

## B3 สีของคลัง

ผู้ใช้ต้องการสีที่สมูทขึ้น โทนน้ำเงินเข้มกับส้ม ปุ่มและแผงเป็นไล่เฉด ใช้ token สีที่ A จะเพิ่มใน `GlassKit` (ระหว่างรอ ให้ใช้ค่าสีของตัวเองในไฟล์ `Gallery*.kt` แล้วเปลี่ยนไปใช้ token ทีหลัง) พื้นหลังหน้าแกลเลอรีควรไล่จากน้ำเงินเข้มเกือบดำ ไม่ใช่ดำล้วนแบบตอนนี้

## B4 หน้าตั้งค่า

เลื่อนเนื้อหาลงมา หัวข้อกับปุ่มย้อนกลับชิดขอบบนเกินไปบนเครื่องจริง (ภาพที่ 6) ให้เพิ่ม padding ด้านบนอย่างน้อยเท่า status bar inset บวกอีกประมาณ 16 dp และนำโทนสีใหม่ไปใช้ ตรวจที่ font 2.0 ด้วย

## B5 ชื่อและไอคอนแอป

**รอผู้ใช้เลือกชื่อ** แล้วจึงแก้ `app_name` และ label ใน manifest ชื่อ package `th.ogay.luma` ห้ามเปลี่ยน (จะกระทบการอัปเดตและข้อมูลเดิม) ไอคอน: วาดเป็น adaptive icon แบบ vector ร่างสองแบบ แนวคือวงแหวนเลนส์กระจกใสมีแสงไล่สีน้ำเงินเข้มไปส้มอ่อนด้านหนึ่ง พื้นหลังเข้ม ไม่ใช้รูปกล้องตรง ๆ และห้ามลอกไอคอนของแอปอื่น ก่อนปิดงานให้แสดงสองแบบให้ผู้ใช้เลือก

## B6 SuperZoom 200x

เขียนโมดูลขยายภาพเป็นไฟล์ใหม่ที่ implement อินเทอร์เฟซ `SuperZoom` ใน `ROUND3_PLAN.md`

- commit แรกให้มีอินเทอร์เฟซกับตัวจริงแบบง่าย (Lanczos/bicubic + sharpen) เพื่อให้ A ต่อสายได้ทันที
- จากนั้นค่อยเพิ่มตัวขยายด้วยโมเดล on-device ถ้าทำได้จริงโดยไม่ขึ้นกับเครือข่าย (เช่น โมเดล super-resolution ขนาดเล็กผ่าน TFLite หรือ ONNX Runtime) ตรวจสิทธิ์การใช้โมเดลก่อนนำมาใส่แอป ใช้เฉพาะโมเดลที่ใบอนุญาตอนุญาตให้ใช้ในแอปเชิงพาณิชย์ และบันทึกที่มาลงเอกสาร อย่าใส่โมเดลที่ไม่ทราบที่มา
- เครือข่ายของ workspace ถูกจำกัด ถ้าดาวน์โหลดโมเดลไม่ได้ ให้ทำเป็นรอผู้ใช้ใส่ไฟล์ แล้วคืนตัวขยายแบบง่ายไปก่อน
- คุมหน่วยความจำ ประมวลผลนอก main thread คืน `null` ถ้าอุปกรณ์ไม่พร้อม และต้องมีเวลาประมวลผลสูงสุด
- ต้องมี unit test อย่างน้อยครอบคลุมการคำนวณขนาดเป้าหมายและกรณีขอบ (ratio ต่ำกว่า 1, เกิน `maxRatio`)
- บอกผู้ใช้ตรง ๆ ว่าที่ 200x ภาพคือการประมาณ ไม่ใช่รายละเอียดจริง
