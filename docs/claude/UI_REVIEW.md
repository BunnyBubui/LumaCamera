# รีวิว UI แบบ read-only

สถานะ: **ยังไม่ได้ทดสอบบนเครื่อง** ข้อค้นพบทั้งหมดมาจากการอ่านซอร์สโค้ดใน `v0.3-studio` commit `9ba0844` และยังไม่ได้ยืนยันบน Reno15 หรือ emulator เอกสารนี้ไม่ได้แก้โค้ด

ขอบเขตที่รีวิวคือ UI รุ่น 0.2 ที่อยู่ใน branch ได้แก่ `CameraActivity.kt`, `CaptureSettings.kt`, `Ui.kt`, `CompositionOverlay.kt` และ `GalleryActivity.kt` ไฟล์ UI ของรุ่น 0.3 ที่ `docs/CLAUDE_HANDOFF.md` ระบุว่าเขียนแล้ว เช่น `StudioUi.kt`, แถบปัดโหมด, แผงตั้งค่าด่วน และไม้บรรทัดซูม ยังไม่อยู่ใน branch จึงยังรีวิวไม่ได้ เมื่อไฟล์เหล่านั้นเข้ามา ข้อ 1, 2, 3 และ 6 ด้านล่างน่าจะยังใช้ได้ เพราะเป็นรูปแบบที่ควรตรวจในทุกหน้าจอ

เลขบรรทัดอ้างอิง commit `9ba0844`

## ข้อค้นพบ

### 1. สถานะ "เลือกอยู่" แสดงด้วยสีอย่างเดียว

ปุ่มรูปแบบภาพ (`CameraActivity.kt:355`), ปุ่มซูม (`:376`) และปุ่มจำนวนเฟรมในแผงตั้งค่า (`CaptureSettings.kt:41-45`) บอกว่าตัวไหนเลือกอยู่ด้วยการเปลี่ยนสีตัวอักษรจากขาว (`#F4F5EC`) เป็นเขียวมะนาว (`#DAEE8D`) อย่างเดียว ผมคำนวณ contrast ratio ระหว่างสองสีนี้ได้ 1.15:1 แปลว่าความสว่างแทบเท่ากัน คนที่แยกสีเขียวได้ไม่ดี หรือคนที่มองจอกลางแดด จะแยกไม่ออกว่าปุ่มไหนเลือกอยู่ นอกจากนี้ TalkBack ก็ไม่รู้สถานะนี้ เพราะโค้ดไม่ได้ตั้ง `isSelected` หรือ `stateDescription`

ข้อเสนอคือเพิ่มสัญญาณที่ไม่ใช่สี เช่น พื้นหลังทึบหรือเส้นใต้สำหรับตัวที่เลือก และตั้ง `isSelected = true` ให้ TalkBack อ่านว่า "เลือกแล้ว"

### 2. ข้อความผลการถ่ายไม่ถูกอ่านโดย TalkBack

ข้อความ "บันทึกรูปแล้ว", "ถ่าย n/n เฟรม · แตะเพื่อหยุด" และ "โฟกัส" แสดงใน `viewfinderNotice` (`CameraActivity.kt:226-228`) ผ่านฟังก์ชัน `hint()` (`:404-408`) แต่ view นี้ไม่ได้ตั้ง accessibility live region ผู้ใช้ TalkBack จึงไม่รู้ว่าถ่ายสำเร็จหรือล้มเหลว นอกจากนี้ข้อความผลการถ่ายหายไปหลัง 2.2 วินาที ซึ่งสั้นสำหรับคนอ่านช้า

ข้อเสนอคือตั้ง `ViewCompat.setAccessibilityLiveRegion(viewfinderNotice, ACCESSIBILITY_LIVE_REGION_POLITE)` สำหรับข้อความผลลัพธ์ และไม่ประกาศความคืบหน้าทุกเฟรม เพราะการถ่าย 32 เฟรมจะทำให้ TalkBack พูดไม่หยุด

### 3. ความสูงตายตัวกับฟอนต์ใหญ่

ข้อความใช้หน่วย sp จึงขยายตามการตั้งค่าฟอนต์ของระบบ (Android 14 ขยายได้ถึง 200%) แต่กล่องที่ใส่ข้อความมีขนาดตายตัวเป็น dp ได้แก่ แถบหัว 60 dp (`CameraActivity.kt:151`), แถวรูปแบบภาพ 52 dp (`:166`), ปุ่ม pill สูง 44 dp (`:178` และ `GalleryActivity.kt:113`), ปุ่มซูมกว้าง 49 dp (`:373`) และแถวสวิตช์ในแผงตั้งค่า 52 dp (`CaptureSettings.kt:36`) เมื่อฟอนต์ใหญ่ ข้อความเช่น "RAW + AI" หรือ "3.5×" น่าจะถูกตัด ต้องยืนยันด้วยการทดสอบ F07 ใน `RENO15_TEST_PROTOCOL.md`

ข้อเสนอคือใช้ความสูงแบบ `WRAP_CONTENT` คู่กับ `minHeight` แทนความสูงตายตัว

### 4. เมนูโหมดซูมปนเรื่องอื่น

ปุ่มเมนูสามจุดเปิด dialog ชื่อ "โหมดซูมกล้องหลัง" (`CameraActivity.kt:415-416`) ซึ่งแสดงตัวเลือกแบบ radio สี่ตัว สองตัวแรกเป็นโหมดซูมจริง แต่ตัวที่สามเปิดข้อมูลเครื่อง และตัวที่สี่เปิดแผงตั้งค่า ผู้ใช้ทั่วไปจะไม่คาดว่าการตั้งค่าเสียงอยู่ใต้หัวข้อโหมดซูม และ TalkBack จะอ่านตัวเลือกที่สามและสี่ว่าเป็นปุ่ม radio ที่ยังไม่เลือก

ข้อเสนอคือแยกเมนูออกเป็นปุ่มตั้งค่าหนึ่งปุ่ม แล้วย้ายโหมดซูมกับข้อมูลเครื่องเข้าไปเป็นหัวข้อในแผงตั้งค่า

### 5. ปุ่ม RAW ที่เครื่องไม่รองรับยังกดได้

เมื่อเครื่องไม่เปิด RAW + JPEG ให้แอป ปุ่ม RAW และ RAW + AI จะจางลงเหลือ alpha 0.4 (`CameraActivity.kt:356`) แต่ยังกดได้ และเมื่อกดจะขึ้น Toast ว่าไม่รองรับ (`:170`) เอกสารส่งต่อกำหนดว่า "ไม่เสนอปุ่มที่กดแล้วทำงานไม่ได้" ปุ่มนี้จึงขัดกับกติกานั้น ถึงจะบอกเหตุผลก็ตาม

ข้อเสนอคือซ่อนปุ่มทั้งสองเมื่อเครื่องไม่รองรับ แผงตั้งค่ามีข้อความ "กล้องนี้ยังไม่เปิด RAW + JPEG ให้แอป" อยู่แล้ว (`CaptureSettings.kt:59`) ผู้ใช้ที่อยากรู้จึงยังหาคำอธิบายได้

### 6. ปุ่มวาดเองไม่บอกว่าเป็นปุ่ม

ชัตเตอร์ ปุ่มสลับกล้อง ปุ่มอัลบั้ม และปุ่มเมนูเป็น class `Glyph` ที่สืบทอดจาก `View` ธรรมดา (`Ui.kt:53-59`) โค้ดตั้ง `contentDescription` ไว้แล้ว แต่ไม่ได้บอกประเภทของ view TalkBack จึงอาจอ่านแค่ "ถ่ายภาพ" โดยไม่บอกว่าเป็นปุ่ม ต้องยืนยันในการทดสอบ F06

ข้อเสนอคือ override `getAccessibilityClassName()` ให้คืน `android.widget.Button` หรือใช้ `ViewCompat.setAccessibilityDelegate` ตั้ง class name

### 7. พื้นที่แตะต่ำกว่าที่แนะนำ

ปุ่ม pill มี `minHeight` 44 dp (`Ui.kt:31`) และปุ่มซูมมีขนาด 49 × 44 dp (`CameraActivity.kt:225` และ `:373`) แนวทาง accessibility ของ Android แนะนำพื้นที่แตะอย่างน้อย 48 × 48 dp ข้อนี้ไม่ร้ายแรง แต่ปุ่มซูมอยู่ติดกันหลายปุ่ม จึงเสี่ยงแตะพลาดเมื่อถือเครื่องมือเดียว

### 8. แถบเลื่อนซูมซ่อนอยู่

แถบเลื่อนซูมจะปรากฏเมื่อกดค้างที่ป้ายซูมมุมซ้ายบน (`CameraActivity.kt:224`) หรือกดค้างที่ปุ่มซูม (`:372`) หน้าจอไม่มีคำใบ้ว่ามีความสามารถนี้ ผู้ใช้ส่วนใหญ่จึงจะไม่พบ ข้อเสนอคือแสดงแถบเลื่อนเมื่อเริ่มบีบซูมแล้วซ่อนเองหลังหยุด หรือแสดงคำใบ้ครั้งแรกที่เปิดแอป

### 9. ช่องมองภาพไม่มีคำอธิบาย

`PreviewView` (`CameraActivity.kt:192-195`) ไม่มี `contentDescription` เมื่อ TalkBack โฟกัสที่ช่องมองภาพจึงไม่มีอะไรให้อ่าน ข้อเสนอคือตั้งคำอธิบาย เช่น "ช่องมองภาพ กล้องหลัง 2×" และอัปเดตเมื่อเปลี่ยนกล้องหรือซูม

### 10. การหมุนจอสร้างทุกอย่างใหม่

Activity จัดการการหมุนเอง (`configChanges` ใน manifest) แต่เมื่อหมุน โค้ดเรียก `buildScreen()` และ `bind()` ใหม่ทั้งหมด (`CameraActivity.kt:138-142`) การผูกกล้องใหม่ทำให้ภาพสดดับชั่วครู่ทุกครั้งที่หมุน แอปกล้องหลายตัวล็อกหน้าจอเป็นแนวตั้งแล้วหมุนเฉพาะไอคอนแทน ข้อเสนอคือวัดระยะเวลาที่ภาพสดดับในการทดสอบ F08 ก่อนตัดสินใจว่าคุ้มที่จะเปลี่ยนหรือไม่

### 11. แฟลชมีแค่เปิด/ปิด

ปุ่มแฟลชสลับระหว่าง `FLASH_MODE_OFF` กับ `FLASH_MODE_ON` เท่านั้น (`CameraActivity.kt:410-413`) ขณะที่ CameraX มี `FLASH_MODE_AUTO` ให้ใช้ด้วย ข้อเสนอคือเพิ่มโหมดอัตโนมัติเป็นสถานะที่สาม

### 12. ถ่าย JPEG ภาพเดียวไม่ตรวจพื้นที่ว่าง

การถ่ายหลายเฟรมตรวจพื้นที่ว่าง 24 MB ก่อนทุกเฟรม (`BurstCapture.kt:71`) และงาน AI ตรวจก่อนเริ่ม (`EnhanceWorker.kt:27`) แต่การถ่าย JPEG ภาพเดียว (`CameraActivity.kt:488-532`) ไม่ตรวจ เมื่อพื้นที่เต็ม ผู้ใช้จะเห็นข้อความทั่วไป "บันทึกรูปไม่สำเร็จ" แทนข้อความที่บอกสาเหตุ ข้อเสนอคือตรวจพื้นที่ก่อนถ่ายแบบเดียวกับการถ่ายหลายเฟรม

## สิ่งที่ทำได้ดีแล้ว

ทุกปุ่มที่ผมอ่านมี `contentDescription` ภาษาไทย ตัวเลือกเสียงชัตเตอร์เคารพข้อบังคับของประเทศที่ต้องมีเสียง (`CaptureSettings.kt:26`) การตั้งค่า "ลดการเคลื่อนไหว" ครอบคลุมทั้งการกดปุ่มและการซูม (`Ui.kt:86`, `CameraActivity.kt:338`) ป้ายซูมแสดงอัตราซูมและ "หลัง/หน้า" โดยไม่อ้างชื่อเลนส์ ซึ่งตรงกับกติกาในเอกสารส่งต่อที่ห้ามใช้เลขซูมแทนชื่อเลนส์โดยไม่มี physical camera ID และ contrast ของข้อความหลักกับพื้นหลังสูงพอ (ข้อความรองสี `#B4BCAE` บนพื้น `#121613` ได้ 9.34:1)

## เรื่องความคุ้นเคยแบบกล้อง OPPO

ผมไม่มีเครื่อง OPPO ให้ดูหน้าจอจริง จึงไม่เขียนว่าแอปกล้อง OPPO วางปุ่มอย่างไร ข้อเสนอเดียวที่ผมให้ได้จากโค้ดคือ ตอนนี้แถวเลือกรูปแบบภาพอยู่ด้านบนใต้แถบหัว (`CameraActivity.kt:166`) ซึ่งไกลจากนิ้วโป้งเมื่อถือเครื่องมือเดียว ให้เจ้าของโปรเจกต์ถ่ายภาพหน้าจอแอปกล้อง OPPO บน Reno15 มาวางเทียบ แล้วตัดสินตำแหน่งของแถบโหมดจากภาพนั้น


## การตอบข้อค้นพบใน Studio 0.3 (Codex integration)

ปรับโค้ดตามข้อ 1/2/4/5/6/7/8/9/11/12 แล้ว: ปุ่มเลือกมีพื้นหลังทึบ รูปร่างต่างกันและ selected/stateDescription; ผลถ่ายมี polite live region พร้อม recommended timeout โดยไม่อ่านทุกเฟรม; เมนูไม่ใช้ radio กับคำสั่ง; ซ่อน RAW ที่ไม่รองรับและแจ้งเมื่อเปลี่ยนกล้อง; Glyph เป็น button role; เพิ่มพื้นที่หลักเป็น 48 dp; บีบซูมเปิดไม้บรรทัดและมี accessibility range/actions; ช่องมองภาพมีคำอธิบาย; แฟลชมี Auto; JPEG ตรวจพื้นที่ว่าง

แผงตั้งค่าหลักใช้ความสูงข้อความแบบ wrap เพิ่มขึ้น แต่ฟอนต์ 200%, TalkBack จริง และเวลาที่พรีวิวดับเมื่อหมุนจอยังต้องตรวจบนอุปกรณ์ ไม่ถือว่า F06/F07/F08 ผ่านจากการแก้ source เพียงอย่างเดียว เอกสารส่วนบนและเลขบรรทัดคงอ้างอิง 9ba0844 ตามรีวิวเดิม
