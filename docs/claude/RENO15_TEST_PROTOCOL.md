# แผนทดสอบเครื่องจริง Reno15 (CPH2825)

สถานะ: **ยังไม่ได้ทดสอบ** เอกสารนี้เป็นวิธีทดสอบที่เขียนจากซอร์สโค้ดใน `v0.3-studio` commit `9ba0844` ซึ่งยังเป็นแอปรุ่น 0.2 ตัวเลขทุกช่องในตารางผลต้องมาจากการวัดจริงพร้อมไฟล์หลักฐาน ห้ามเติมตัวเลขโดยไม่มีไฟล์

โหมดที่ยังไม่อยู่ใน branch เช่น วิดีโอ, slow-motion, RAW video และ PRO มีวิธีวัดเตรียมไว้ในหัวข้อ "วัดเมื่อโหมดเข้า branch แล้ว" ให้ทดสอบเมื่อโค้ดของโหมดนั้นเข้ามาแล้วเท่านั้น

## 1. ก่อนเริ่ม

เครื่องมือที่ต้องมีคือ Reno15 ที่เปิด USB debugging, คอมพิวเตอร์ที่มี `adb`, FFmpeg (`ffprobe`), ExifTool, ขาตั้งกล้อง, ป้ายตัวหนังสือไทยพิมพ์หลายขนาด (เช่น 8, 12, 24 และ 48 pt บนกระดาษ A4) และอุปกรณ์ที่ให้แสงกะพริบพร้อมเสียงบี๊บในเวลาเดียวกัน (เช่น มือถืออีกเครื่องที่เปิดวิดีโอทดสอบ A/V sync)

บันทึกข้อมูลรุ่นที่ทดสอบทุกครั้ง ได้แก่ commit จาก `commit.txt` ใน artifact ของ GitHub Actions, SHA-256 ของ APK, ชื่อแพ็กเกจ (`com.lumora` สำหรับ debug หรือ `com.lumora.beta` สำหรับ beta) และ build fingerprint ของเครื่อง

```bash
adb shell getprop ro.build.fingerprint > device/fingerprint.txt
adb shell dumpsys media.camera > device/camera_dump.txt
adb shell dumpsys package th.ogay.luma.dev | grep versionCode > device/app_version.txt
```

ไฟล์ `camera_dump.txt` คือหลักฐานเดียวที่ใช้บอกว่าแอปเข้าถึงกล้องอะไรได้ ให้จดค่าต่อไปนี้จากไฟล์ลงตารางในหัวข้อ 6 ก่อนทดสอบอย่างอื่น ได้แก่ camera ID แบบ logical และ physical, capabilities (`RAW`, `LOGICAL_MULTI_CAMERA`, `MANUAL_SENSOR`, `CONSTRAINED_HIGH_SPEED_VIDEO`), ช่วง zoom ratio, `SENSOR_INFO_TIMESTAMP_SOURCE` และขนาดภาพที่รองรับ ห้ามใช้สเปกจากเว็บ OPPO แทนค่าในไฟล์นี้

## 2. วิธีบันทึกผล

ให้แต่ละการทดสอบมีโฟลเดอร์ชื่อตามรหัส เช่น `results/F06/` เก็บภาพหน้าจอ วิดีโอหน้าจอ (`adb shell screenrecord`) logcat และไฟล์ภาพที่ได้ แล้วกรอกตารางนี้

| รหัส | build | สภาพแวดล้อม | ผลที่คาด | ผลจริง | ผ่าน/ไม่ผ่าน | ไฟล์หลักฐาน |
|---|---|---|---|---|---|---|

เก็บ logcat ของแอประหว่างทดสอบด้วยคำสั่ง

```bash
adb logcat -c && adb logcat --pid=$(adb shell pidof th.ogay.luma.dev) > results/<รหัส>/logcat.txt
```

## 5. วัดเมื่อโหมดเข้า branch แล้ว

หัวข้อนี้เตรียมวิธีวัดไว้ล่วงหน้าสำหรับโหมดที่แผน 0.3 ระบุไว้แต่ยังไม่มีโค้ดใน branch

**fps จาก timestamp ของ sample** ให้ถ่ายวิดีโอฉากนิ่ง 60 วินาทีที่แต่ละค่า fps แล้วดึงเวลา packet ด้วยคำสั่งด้านล่าง จากนั้นคำนวณ fps เฉลี่ยจาก (จำนวนเฟรม − 1) หารด้วยช่วงเวลารวม และนับเฟรมที่ห่างจากเฟรมก่อนหน้าเกิน 1.5 เท่าของช่วงเฟรมปกติเป็นเฟรมหาย ห้ามใช้ค่า `r_frame_rate` ในไฟล์เป็นผลวัด เพราะค่านั้นเป็นค่าที่ประกาศไว้ ไม่ใช่ค่าที่เกิดจริง

```bash
ffprobe -v error -select_streams v:0 -show_entries packet=pts_time -of csv=p=0 clip.mp4 > pts.csv
```

**A/V sync** ให้ถ่ายแหล่งที่กะพริบแสงพร้อมเสียงบี๊บ 10 ครั้ง แล้วหาเวลาที่เสียงเริ่มดังจากคลื่นเสียง และเวลาที่ความสว่างของภาพกระโดดจากเฟรมวิดีโอ ผลต่างของสองเวลานี้คือค่าเหลื่อม ITU-R BT.1359 ระบุว่าคนเริ่มสังเกตได้เมื่อเสียงนำภาพเกิน 45 ms หรือตามภาพเกิน 125 ms ให้ใช้ช่วงนี้เป็นเป้าหมายเบื้องต้น และบันทึกค่า `SENSOR_INFO_TIMESTAMP_SOURCE` จากหัวข้อ 1 ประกอบ เพราะถ้าค่าเป็น `UNKNOWN` เวลาของภาพเทียบกับนาฬิกาเสียงโดยตรงไม่ได้

**RAW video (DNG sequence)** ให้นับจำนวนไฟล์ DNG เทียบกับระยะเวลาคูณ fps ที่ขอ ดึง timestamp ของแต่ละเฟรมที่แอปบันทึกไว้ แล้วนับช่องว่างที่เกิน 1.5 เท่าของช่วงเฟรมเป็นเฟรมหาย ความเร็วเขียนคำนวณจากขนาดไฟล์รวมหารด้วยระยะเวลาที่ถ่าย ให้ระบุด้วยว่า timestamp มาจาก `SENSOR_TIMESTAMP` หรือนาฬิกาของแอป การที่ได้ DNG ภาพเดียวไม่ได้ยืนยันว่าถ่ายต่อเนื่องได้ตาม fps ที่ขอ

**คู่ค่าที่ใช้ได้จริง** ให้กรอกตารางด้านล่างจากการถ่ายจริงเท่านั้น โดยตรวจไฟล์ผลลัพธ์ด้วย `ffprobe -show_streams` คอลัมน์ HDR ให้ดู `color_transfer` (เช่น `smpte2084` หรือ `arib-std-b67`) ส่วนคอลัมน์ "แอปเสนอ" ให้ดูว่าแอปแสดงตัวเลือกนั้นหรือไม่ ซึ่งต้องตรงกับสิ่งที่ CameraX หรือ Camera2 รายงานว่ารองรับ

| ความละเอียด | fps ที่ขอ | fps ที่วัดได้ | HDR ที่ขอ | color_transfer ในไฟล์ | กันสั่น | แอปเสนอ | ใช้ได้จริง | ไฟล์หลักฐาน |
|---|---|---|---|---|---|---|---|---|

**การควบคุมแบบ PRO** ให้ตั้ง ISO, shutter, WB และ focus ทีละค่า ถ่าย แล้วเทียบค่าที่ขอกับค่าที่บันทึกใน EXIF/DNG (`exiftool -ISO -ExposureTime -WhiteBalance`) จากนั้นสลับกลับเป็น AUTO แล้วถ่ายอีกภาพเพื่อตรวจว่าค่ากลับเป็นอัตโนมัติจริง

## 7. เทียบคุณภาพภาพ

ถ่ายด้วย Luma และแอปกล้อง OPPO จากขาตั้งตำแหน่งเดียวกัน ระยะซูมเดียวกัน (1×, 2×, 3.5×) ทั้งกลางวันและแสงน้อย ฉากที่ต้องถ่ายคือป้ายตัวหนังสือไทย ใบหน้า ลายผ้า และฉากที่มีวัตถุเคลื่อนที่ จากนั้นให้คนอย่างน้อย 3 คนดูภาพคู่แบบสุ่มลำดับโดยไม่บอกว่าภาพไหนมาจากแอปไหน แล้วเลือกภาพที่อ่านตัวหนังสือได้ชัดกว่า บันทึกผลเป็นจำนวนครั้งที่แต่ละแอปถูกเลือก สำหรับป้ายตัวหนังสือ ให้จดขนาดตัวอักษรเล็กสุดที่ยังอ่านถูกทุกตัวด้วย
