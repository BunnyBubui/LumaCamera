## รายการของ Claude A (กล้องและ UI กลาง)

### ระบบ UI กลาง
- **A1 โทนสีไล่เฉด:** ปุ่ม หน้าต่าง แผง และเมนูทุกที่ใช้เฉดน้ำเงินเข้มกับส้มตามธีม ทำเป็น token ใน `GlassKit` (เช่น `Glass.gradientNavy`, `Glass.gradientAccent`) ให้ B เรียกใช้ได้
- **A2 ความนุ่ม:** ขอบตกแต่งด้านบนของแผงดูซ้อนกันแปลก (เห็นเป็นสองชั้นในภาพแรก) ให้เหลือขอบเดียวที่ละมุน เพิ่มมุมโค้ง ลดความคมของเส้นขอบและเงาบนปุ่มทุกปุ่ม
- **A3 เบลอ:** ปัจจุบันเบลอผิดที่ ภาพที่ 2 เห็นแผงข้างหลังถูกเบลอปนกับเมนู ให้เบลอเฉพาะสิ่งที่ไม่เกี่ยวข้องกับสิ่งที่กำลังใช้ และทำให้เป็นเบลอชั้นเดียว ไม่ซ้อนกัน
- **A4 เมนูแบบ iPhone:** dropdown (เช่น รูปแบบไฟล์) ให้กดค้างแล้วเลื่อนนิ้วไปมาเพื่อเลือก ปล่อยนิ้วแล้วยืนยันค่านั้น ไฮไลต์เลื่อนตามนิ้ว และยังแตะเลือกได้แบบเดิม
- **A5 ปุ่ม slider ติดขอบ:** ภาพที่ 3 ปุ่มหมุดของ slider ชิดขอบซ้ายขวาของแผงจนเกือบโดนตัด เพิ่ม padding ด้านข้างของแถบ slider
- **A6 หน้าวิดีโอกลมกลืน:** ให้วิดีโอธรรมดา วิดีโอโปร และสโลว์โมชันใช้โครงเดียวกันกับหน้ากล้องภาพถ่าย ไม่แยกเป็นหน้าต่างหรือ modal ต่างหาก (ตอนนี้ภาพที่ 3 เป็นหน้าแยกที่มีแถบหัวของตัวเอง)
- **A7 ความลื่น 120 fps:** ลดงานต่อเฟรมให้ UI วิ่งเต็ม 120 Hz บนจอ Reno15 ตรวจ overdraw, การสร้าง object ในลูปวาด, shader และ animation ที่ไม่จำเป็น ขอ `preferredDisplayModeId` สูงสุดที่จอรองรับ

### กล้องและการถ่าย
- **A8 วิดีโอ 60 fps ยังใช้ไม่ได้:** ภาพที่ 3 ตัวเลือก FPS มีแค่ 30 ที่ SD และ HDR สืบหาสาเหตุให้ชัด ดูว่า `VideoSessions.rates()` รายงานอะไรต่อความละเอียดแต่ละระดับ, ทดลองไม่เปิด HDR/EIS ที่ 60, ลองเส้นทาง Camera2 ตรง (`CONTROL_AE_TARGET_FPS_RANGE`) ถ้า CameraX ไม่ให้ และเขียนผลสำรวจของเครื่องลงเอกสาร ถ้าฮาร์ดแวร์หรือ OPPO ล็อก 60 ไว้ให้ระบุเหตุผลตรง ๆ แทนการซ่อนตัวเลือก
- **A9 Log หลายแบบในวิดีโอ:** เพิ่มโปรไฟล์ Log ให้เลือก เช่น Log แบน (มีอยู่), Log นุ่ม, โปรไฟล์ภาพจืดสำหรับเกรด และ HLG10 ใช้ชื่อกลาง ๆ ห้ามใช้ชื่อ "C-Log" เพราะเป็นเครื่องหมายการค้า
- **A10 ภาพ RAW แบบ Log พร้อมพรีวิว:** ในโหมดถ่ายภาพ เพิ่มตัวเลือก RAW ที่แสดงพรีวิวแบบ Log แบนบนจอขณะถ่าย (ใช้เส้นโทนบนพรีวิวเท่านั้น ไฟล์ DNG ยังเป็นข้อมูลดิบจากเซนเซอร์) และมีสวิตช์เปิดปิดพรีวิว
- **A11 ภาพบุคคลปรับ f:** เพิ่มปุ่มเลือกค่า f ในโหมดบุคคล หมายเหตุ: กล้องมือถือรูรับแสงคงที่ ค่า f นี้เป็นความแรงของเบลอพื้นหลังจำลอง ให้บอกผู้ใช้ตรง ๆ ไม่ให้เข้าใจว่าเป็นรูรับแสงจริง
- **A12 WB สีเพี้ยน:** ภาพที่ 5 ที่ 4100K ภาพออกเขียวเหมือนถูกย้อม ตรวจ `kelvinGains` และ `cameraToSrgb` ที่ใช้ `COLOR_CORRECTION_TRANSFORM` กับ gains ว่าลำดับแชนเนลและเมทริกซ์ถูกต้อง เทียบกับ AWB ของกล้องที่ค่าอุณหภูมิเดียวกัน ถ้าไม่แน่ใจให้ใช้ `COLOR_CORRECTION_MODE_FAST/HIGH_QUALITY` ร่วมกับ AWB lock เป็นทางสำรอง
- **A13 ปรับสมดุลแสงสีให้ครบ:** เพิ่มการปรับ WB เป็น tint (เขียว-ม่วง) และค่าอื่นที่เซนเซอร์ให้ปรับได้ทั้งหมด เช่น สีสัน ความคมชัด การลดนอยส์ โดยอ่านจาก `CameraCharacteristics` ว่าเครื่องรองรับอะไร และซ่อนสิ่งที่ไม่รองรับ
- **A14 ซูมลื่นแบบเลนส์:** ซูมต่อเนื่องแบบอนุพันธ์ ไม่กระโดดตอนสลับเลนส์ ใช้ `setZoomRatio` ต่อเนื่องและทำ easing ตามความเร็วนิ้ว
- **A15 เอาซูมอัตโนมัติออก:** ลบฟังก์ชันและตัวเลือกซูมอัตโนมัติทั้งหมดออกจากโค้ดและหน้าตั้งค่าที่เกี่ยวข้อง (ตัวเลือกใน `StudioSettings.kt` ให้ B ลบ)
- **A16 เมตาเลนส์ตอนถ่าย:** บันทึกข้อมูลเลนส์ลง EXIF ของภาพ (ความยาวโฟกัสจริงและเทียบ 35 มม., ค่ารูรับแสง, ชื่อเลนส์ เช่น กว้าง/หลัก/เทเล) และลงไฟล์ JSON ข้างวิดีโอ
- **A17 รองรับซูม 200x:** ฝั่ง A ทำเฉพาะตัวควบคุมซูมให้ลากถึง 200x และเรียกใช้โมดูลของ B เมื่อเกินซูมออปติคอล โดยดึงเฟรมไปให้ `SuperZoom` ประมวลผล (ดูข้อต่อกับ B ด้านล่าง)

รายละเอียดเต็มอยู่ใน `ROUND3_CLAUDE_B_TASK.md`

- **B2 คลังภาพทั้งหมด:** ออกแบบแถบอัลบั้มใหม่หนึ่งแถบ เลื่อนซ้ายขวาได้ แยกตามอัลบั้ม มีปุ่ม "ดูเพิ่มเติม" และแก้ปัญหาภาพหาย แถบบนล่องหน หน้าดูภาพไม่มีทางไปรูปทั้งหมด
- **B3 สีของคลัง:** ตกแต่งสีของแกลเลอรีให้สมูทขึ้นด้วยโทนน้ำเงินเข้มกับส้ม
- **B4 หน้าตั้งค่า:** เพิ่ม padding ด้านบนลงมา (ภาพที่ 6 หัวข้อชิดขอบบนเกินไป) และนำโทนสีใหม่ไปใช้
- **B5 ชื่อและไอคอนใหม่:** เปลี่ยนชื่อแอปกับไอคอน (รอผู้ใช้เลือกชื่อก่อน ดูหัวข้อ "สิ่งที่ยังต้องรอผู้ใช้")
- **B6 SuperZoom 200x:** เขียนโมดูลขยายภาพด้วย AI เป็นไฟล์ใหม่ `SuperZoom*.kt` ให้ A เรียกใช้
- **B7 ลบตัวเลือกซูมอัตโนมัติ** ออกจาก `StudioSettings.kt`

## ข้อต่อระหว่าง A และ B

ให้ B เปิดเผยอินเทอร์เฟซนี้ใน `SuperZoom.kt` ตั้งแต่ commit แรก แม้ข้างในยังเป็นของชั่วคราว เพื่อให้ A เรียกใช้ได้เลย

```kotlin
interface SuperZoom {
    /** ซูมสูงสุดที่รองรับ เช่น 200f */
    val maxRatio: Float
    /** ขยายภาพจาก crop ของเฟรมจริงเป็นภาพขนาด target ถ้ายังไม่พร้อมให้คืน null */
    suspend fun upscale(source: android.graphics.Bitmap, ratio: Float): android.graphics.Bitmap?
}
```

A เรียก `upscale` ตอนถ่ายภาพที่ซูมเกินออปติคอล ส่วนพรีวิวสดใช้ digital crop ธรรมดา ไม่ผ่าน AI

## สิ่งที่ยังต้องรอผู้ใช้

- เลือกชื่อแอปใหม่ (ดูรายการที่เสนอไว้ในแชต เช่น Rueang, Praew, Lumora) แล้วแจ้ง B ก่อนทำข้อ B5
- ไอคอน: ผู้ใช้ยังไม่ได้ยืนยันแนว ให้ B ร่างสองแบบเป็น vector แล้วให้ผู้ใช้เลือก

## ความจริงที่ต้องบอกผู้ใช้ตรง ๆ

- ซูม 200x ด้วย AI ได้ภาพที่ดูคมขึ้นแต่ไม่ใช่รายละเอียดจริง ที่ซูมสูงมากภาพจะดูเรียบ/เหมือนสร้างขึ้น และกินเวลาประมวลผลบนเครื่อง
- ค่า f ในโหมดบุคคลเป็นเบลอจำลอง ไม่ใช่รูรับแสงจริง
- ถ้า 60 fps ถูกล็อกโดยระบบ OPPO ให้บอกว่าล็อก ไม่ใช่ซ่อน
- "Log" ในแอปเป็นโทนแบนของเราเอง ไม่ใช่ Log ของค่ายใด
