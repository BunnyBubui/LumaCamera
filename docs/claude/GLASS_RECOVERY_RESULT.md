## สิ่งที่แก้ตามลำดับงาน

**1. เมนูซ้อน (P0)**
`GlassMenu` ที่เปิดบนแผงจะไม่เพิ่มเงามืดชั้นที่สอง ใช้การ์ดทึบ `0xF5222225` และให้แผงด้านล่างจางกับเบลอเล็กน้อยผ่าน `GlassSheet.recede()` เหมือนต้นแบบ
แผงตัวเลือกไม่ปิดแล้วเปิดใหม่หลังเลือกค่าอีกต่อไป ใช้ `GlassSheet.refresh()` สร้างเนื้อหาใหม่ในที่เดิม
เลเยอร์ที่กำลังปิดเป็น `LayerFrame` ซึ่งไม่รับสัมผัส และ shade ที่กำลังจางถูกตั้งเป็นกดไม่ได้ทันที จึงไม่เหลือตัวรับสัมผัสค้าง
การเปิดแผงจะปิดเมนูและ dial ก่อน ปุ่ม Back ปิดชั้นบนสุดตามลำดับ เมนู → ตัวแก้แถบโหมด → แผง → dial โปร
เลือกค่าในเมนูได้ครั้งเดียวต่อการเปิดหนึ่งครั้ง แม้แตะซ้ำเร็ว

**2. ปัดขึ้น (P0)**
แถบล่างเป็น `SwipeColumn` ที่ดักการลากแนวตั้งเมื่อเกิน touch slop ส่วนปุ่มยังกดได้ และ `CenterStrip` ยังปัดแนวนอนได้
ปุ่มจับขนาด 120×48 dp แตะเปิดได้ และแถบล่างมี accessibility action "เปิดตัวเลือกกล้อง"

**3. ลากซูม (P0)**
`ZoomCapsule` ได้ทั้ง stream ตั้งแต่ DOWN แตะที่ปุ่มเลนส์ยังเป็นการเลือกเลนส์ ลากแนวนอนเกิน slop เปลี่ยนเป็นการซูม และขอให้ parent หยุดดัก
ลากต่อบนวงล้อได้ขณะที่ยังแสดงอยู่ เมื่อ CANCEL หรือ `onPause` จะคืนสถานะ ใช้เหมือนกันทั้งกล้องและวิดีโอ

**4. ขอบและชิ้นส่วนขาด (P1)**
- สาเหตุหลักของ cell ท้ายแถบโหมดขาดหรือกดไม่ได้: track ของ `CenterStrip` กว้างเท่ากล่อง จึงตัดและบังสัมผัสของ item ที่อยู่เลยขอบขวา ตอนนี้ track กว้างเท่าเนื้อหาจริง
- `GlassDrawable.getOutline()` ใช้ radius เดียวกับที่วาด ทำให้ `clipToOutline` ของรูปย่อและเงาตรงกับขอบกระจก
- เมนูจำกัดความสูงตามพื้นที่จริงหลังหัก inset ถ้าล้นจะเลื่อนได้
- แนวนอน: แถบล่างย้ายไปด้านข้าง กว้าง 320 dp ทั้งกล้องและวิดีโอ
- แถวที่มีข้อความสองบรรทัดสูงขึ้นตาม font scale คือ 1.0 → 1 เท่า และ 2.0 → 1.5 เท่า ชิปกว้างตามข้อความ ไทล์ในแผงใช้ความสูงขั้นต่ำแทนความสูงตายตัว
- ตัวเลขบนปุ่มเลนส์ใช้หน่วย dp เพราะปุ่มเป็นวงกลมขนาดคงที่

**5. ความลื่น (P1)**
cache SVG `Path` ต่อ icon ด้วย LruCache (เดิม parse ทุก `onDraw`) และ cache shader ของขอบจางใน `CenterStrip`
ภาพค้างตอน rebind ย่อเหลือ 1/3 แล้ว recycle ภาพเก่า ภาพ minimap เก็บเฉพาะเลนส์ 1× และ 3.5× ขนาดกว้าง 240 px ถ่ายซ้ำได้ไม่เกินทุก 1.5 วินาที และคืนหน่วยความจำใน `onPause`
`CenterStrip` ยกเลิก animator เมื่อถูกถอดออกจากจอ **ยังไม่ได้วัด frame timing**

**6. state และ accessibility (P1)**
item ที่เลือกใน `CenterStrip`, `GlassMenu` และแท็บแกลเลอรีมี `isSelected` และ stateDescription "เลือกอยู่"
`CenterStrip` ประกาศตัวเป็น HorizontalScrollView และมี action เลื่อนหน้า/ถอยหลัง ตัวแก้แถบโหมดมี action "เลื่อนขึ้น/ลง" แทนการลาก
ปุ่มที่กดได้ทั้งหมดในกล้อง วิดีโอ ตั้งค่า แกลเลอรี และตัวแก้ ขยายเป็นอย่างน้อย 48 dp

**7. test**
- `GlassNav.kt` (ใหม่) รวม selector ของ UI ใหม่ไว้ที่เดียว
- `CameraFlowTest` และ `StudioFlowTest` เปลี่ยนเฉพาะทางเดินไปยังปุ่ม assertion เรื่องไฟล์ RAW/JPEG/AI, จำนวนเฟรม, dimension, video/audio/pause ไม่ได้แก้
- ตั้งค่าเพิ่มสวิตช์ "ครอปจากกล้องหลัก 1×" (คีย์ `software`) เพราะ test เดิมเปิดค่านี้ผ่าน UI แต่ UI 0.3 ไม่มีทางเปิดแล้ว
- `StudioAccessibilityTest` นับ `CenterStrip` เป็นตัวเลื่อนแบบเดียวกับ HorizontalScrollView และเปิดแผง glass แทนชีต "เพิ่มเติม" เกณฑ์ 48 dp, label และ text-clipped คงเดิม
- `GlassGestureTest` (ใหม่) มีหกกรณี: ปัดขึ้นจากปุ่มจับแล้วถ่ายภาพต่อได้, ปัดขึ้นจากแถบโหมดโดยที่ปัดข้างยังเปลี่ยนโหมด, ลากซูมจากปุ่มเลนส์แล้วแตะกลับ 1×, ปลายแถบโหมดเห็นเต็ม cell และ "+" เปิดตัวแก้เฉพาะเมื่อแตะ, เปิด/ปิดเมนู 20 ครั้งแล้วไม่เหลือชั้นค้าง, หยุด night burst แล้วเก็บเฟรมที่ได้

**8. หยุดถ่ายกลางคืน**
`nightProgress(0, count)` ถูกเรียกทันทีที่เริ่ม burst และ `refresh()` ทั้งตอนเริ่มและตอนจบ ปุ่มชัตเตอร์จึงเป็นปุ่มหยุดตั้งแต่วินาทีแรก

ต้นแบบกับแอปต่างกันหนึ่งจุด: ปัดแถบโหมดจนเลยโหมดสุดท้ายจะหยุดที่โหมดนั้น ไม่เปิดตัวแก้ ส่วน "+" เปิดตัวแก้เมื่อแตะเท่านั้น

## shared method ที่แตะในไฟล์ core

| ไฟล์ | method | สิ่งที่เปลี่ยน |
|---|---|---|
| CameraActivity | `onCreate` | เพิ่ม OnBackPressedCallback ปิดชั้นบนสุด |
| CameraActivity | `onPause` | จบการลากซูม, ซ่อนวงล้อ, คืนภาพ minimap |
| CameraActivity | `takeBurst` | คำนวณจำนวนเฟรมก่อน และเรียก `nightProgress(0, count)` เมื่อเป็นโหมดกลางคืน ส่วน BurstCapture และการล็อก 3A ไม่เปลี่ยน |
| CameraActivity | `showAllSettings` callback | อ่าน `software` ใหม่ก่อน bind |
| VideoActivity | `onCreate` | เพิ่ม back callback ปิด dial ก่อน |
| VideoActivity | `onPause` | จบการลากซูมก่อนโค้ดเดิม |
| VideoActivity | `applyChip` | เรียก `configPending()` ปิดปุ่มอัดทันทีเมื่อชุดเปลี่ยน และ `bind()` เปิดคืนเมื่อสำเร็จ ส่วน debounce 450 ms ยังเป็นของเดิม |

ไม่ได้แตะ `bind`, `startRecording`, `stopRecording`, Finalize และไม่ได้อ่าน FPS เพิ่ม ส่วน `frameRates()` ยังอ่านจาก `supportedFrameRateRanges` ตามเดิม รอเปลี่ยนเป็น `VideoSessions.rates(...)` ตอน Codex รวมงาน
