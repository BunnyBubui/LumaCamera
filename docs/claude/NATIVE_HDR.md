# HDR EF2 — engine native (C++/OpenCV) ที่วางคู่กับ EF1

เอกสารนี้อธิบาย engine HDR ตัวที่สองของแอป ชื่อ EF2 ซึ่งเขียนด้วย C++ และ OpenCV ผ่าน JNI (Java Native Interface คือช่องทางที่โค้ด Kotlin/Java เรียกฟังก์ชัน C++ ได้) EF2 ไม่ได้แทน EF1 (`HdrFusionQuality.java`) แต่เป็นทางเลือกที่ผู้ใช้เปิดเองในหน้าตั้งค่า เพื่อเทียบภาพและเวลากันบนเครื่องจริงก่อนตัดสินว่าจะใช้ตัวไหนเป็นค่าเริ่มต้น

## EF2 ทำอะไร

ลำดับการทำงานตามสเปกที่ผู้ใช้ให้มามีห้าขั้น

1. รวมภาพ 3 ระดับแสงด้วย `cv::createMergeMertens(1, 1, 0)` ได้ภาพ float 0..1
2. แปลงเป็น CIE L\*a\*b\* (ปริภูมิสีที่แยกความสว่าง L\* ออกจากสี a\*, b\*)
3. แยก L\* เป็นชั้นฐาน (base) กับชั้นรายละเอียด (detail) ด้วย guided filter รัศมี 16 พิกเซล eps 0.01 ตัวกรองนี้ทำให้บริเวณเรียบเนียนแต่รักษาขอบที่ต่างกันมาก
4. `detail = L − base`, `L_final = base^0.95 + 1.35 × detail`
5. รวม L_final กับ a\*, b\* เดิม แล้วแปลงกลับเป็นภาพ 8 บิต

ตัวอย่างผลจากเทสต์บนเดสก์ท็อป: หน้าต่างที่ขาวโพลนในภาพ EV 0 มีค่าเบี่ยงเบนมาตรฐานของ luma 0.41 (แทบไม่มีลาย) ภาพ EV −2 มี 11.59 และผล EF2 มี 14.74 คือได้ลายกลับมาและเข้มขึ้นจากการเร่งรายละเอียด

## จุดที่ต่างจากสเปก และเหตุผล

ผมเปลี่ยนสามจุด เพราะถ้าทำตามตัวอักษรจะ build ไม่ได้หรือผลผิด

1. `cv::ximgproc::guidedFilter` อยู่ใน opencv_contrib ซึ่งแพ็กเกจ `org.opencv:opencv` บน Maven ไม่มี ผมจึงเขียน guided filter เองจาก `cv::boxFilter` หกครั้ง (สูตรของ He, Sun และ Tang) ไม่ใช้ `bilateralFilter` เป็นทางสำรอง เพราะรัศมี 16 ช้ามากที่ความละเอียดภาพจริง
2. สเปกให้แปลงเป็น Lab 8 บิตแล้วคูณกลับด้วย 255 ผมใช้ Lab แบบ float แทน และปรับ L\* ให้อยู่ช่วง 0..1 ก่อนกรอง เหตุผลคือ Lab 8 บิตบีบ L\* เหลือ 256 ขั้นก่อนที่ขั้น 4 จะขยายรายละเอียด ซึ่งทำให้เกิดแถบสี (banding) และค่า eps 0.01 กับ `pow(·, 0.95)` มีความหมายเฉพาะบนสเกล 0..1 เท่านั้น สูตรขั้น 4 เหมือนสเปกทุกตัวเลข
3. EF2 รับภาพที่ HdrCapture ถอดรหัสและจัดตำแหน่งแล้ว (ARGB) ไม่ได้รับ YUV จาก `ImageProxy` โดยตรง เพราะ HdrCapture ถ่ายเป็น JPEG อยู่แล้ว การเปลี่ยนเป็น YUV ต้องรื้อ flow ถ่ายภาพ ซึ่งชนกับงาน Glass UI (PR #9) และงานวิดีโอของ Codex ไฟล์ `HDRCameraManager.kt` ในสเปกจึงยังไม่ได้ทำ

ข้อที่ต้องรู้เกี่ยวกับค่าในสเปก: `exposure_weight = 0` ปิดเกณฑ์ well-exposedness ของ Mertens ทำให้ระบบเลือกพิกเซลจากความคมและความอิ่มสีอย่างเดียว ส่วน `pow(base, 0.95)` ทำให้ภาพสว่างขึ้นเล็กน้อย ไม่ได้บีบช่วงแสงมากนัก ผมทำตามค่านี้ แต่ทุกค่าเปลี่ยนได้ผ่าน `HdrNative.Params`

## สิ่งที่ EF2 ยังไม่มีเมื่อเทียบกับ EF1

EF2 ไม่มีการปฏิเสธการเคลื่อนไหว (motion rejection) ถ้าคนหรือรถขยับระหว่างสามเฟรม จะเกิดเงาซ้อน (ghost) ขณะที่ EF1 ตัดบริเวณนั้นออก EF2 ยังยกเลิกกลางขั้น Mertens ไม่ได้ ตรวจการยกเลิกได้เฉพาะระหว่างขั้น ส่วนการจัดตำแหน่ง EF2 ใช้ค่า `dx/dy` เดียวกับ EF1 จาก HdrCapture พิกเซลที่เลื่อนออกนอกภาพจะใช้พิกเซลจากภาพอ้างอิงแทน

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `app/src/main/cpp/hdr_pipeline.h/.cpp` | ขั้น 1–5 ใช้ OpenCV ล้วน ไม่มี JNI จึง build บนเดสก์ท็อปได้ |
| `app/src/main/cpp/hdr_native_bridge.cpp` | JNI: แปลง `int[]` ARGB เป็น `cv::Mat`, เลื่อนภาพ, เขียนผลลง `Bitmap` ด้วย jnigraphics, แปลง error เป็น exception ของ Java |
| `app/src/main/cpp/CMakeLists.txt` | ลิงก์ `libopencv_java4.so` จาก AAR ผ่าน Prefab, ใช้ `c++_shared`, จัดแนว 16 KB |
| `app/src/main/java/th/ogay/luma/hdr/HdrNative.kt` | API ฝั่ง Kotlin: `HdrNative.fuse(...)` |
| `app/src/main/java/th/ogay/luma/HdrCapture.kt` | เลือก EF1/EF2 ตามค่าตั้ง `hdr_native` และถอยไป EF1 เมื่อ EF2 โหลดไม่ได้หรือล้ม |
| `app/src/test/cpp/` | เทสต์บนเดสก์ท็อป 22 ข้อ |
| `app/src/androidTest/.../HdrNativeDeviceTest.kt` | เทสต์บน emulator: library โหลดได้, สีไม่สลับช่อง, ทิศการเลื่อนตรงกับ EF1, การยกเลิกและ error |

## วิธีทดสอบบน Reno15

เปิดหน้าตั้งค่า แล้วเปิด "HDR แบบ native EF2 (ทดลอง)" จากนั้นถ่าย HDR ฉากเดิมสองครั้ง ครั้งแรกเปิด ครั้งที่สองปิด ในแกลเลอรี ป้ายของภาพจะบอกว่าใช้ EF1 หรือ EF2 ส่วน EXIF ImageDescription ของไฟล์ EF2 จะมีเวลา fuse และ tone เป็นมิลลิวินาที ถ้า EF2 ล้ม ไฟล์จะออกมาเป็น EF1 และ EXIF จะบอกชื่อ error

ฉากที่ควรลองคือห้องที่มีหน้าต่างสว่าง (ดูว่าลายนอกหน้าต่างกลับมาไหม) ฉากย้อนแสง และฉากที่มีคนเดินผ่าน (ดูเงาซ้อนของ EF2)

## ผลวัด

| รายการ | ผล |

ตัวเลขเวลาเป็นผลบนเดสก์ท็อปเท่านั้น ยังไม่ได้วัดบน Reno15 HdrCapture จำกัดภาพที่รวมไว้ไม่เกิน 3 ล้านพิกเซลทั้ง EF1 และ EF2 จึงเทียบกันได้ที่ขนาดเดียวกัน
