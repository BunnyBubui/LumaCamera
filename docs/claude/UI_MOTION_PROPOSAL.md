## 2. ค่ากลางของหน้าตา

**สี:** ใช้ค่าเดิมใน `Ui.kt` (`BG`, `WHITE`, `LIME` #FFD447 เป็นสีเน้น) ข้อความรองใช้ขาวโปร่ง 72% แทน `MUTED` บนพื้นกระจก เพราะ `MUTED` บนกระจกเข้มได้ความต่างสีไม่ถึง 4.5:1 ในบางฉาก

**ระยะ:** ตาราง 4dp ใช้ 4 / 8 / 12 / 16 / 24 / 36

- ปุ่มในกลุ่มเดียวกันห่าง 6–8dp
- ขอบในของแคปซูลกระจก 4–6dp
- แถวล่าง (รูปย่อ ชัตเตอร์ สลับกล้อง) เว้นขอบซ้ายขวา 36dp
- ชีตลอยห่างขอบจอ 8dp มุมโค้ง 34dp

**ขนาดปุ่ม:** ต้นแบบใช้ 44 หน่วย บน Android ให้ใช้อย่างน้อย 48dp ตามเกณฑ์ที่ `StudioAccessibilityTest` ของงาน D ตรวจ ชัตเตอร์ 80dp รูปย่อและสลับกล้อง 56dp

**ไอคอน:** เส้นหนา 1.8 จาก 24 หน่วย ปลายมน แนะนำให้ทำเป็น VectorDrawable ใน `res/drawable/` (ไม่ต้องเพิ่ม dependency) แล้วค่อยเลิกใช้ `Glyph` ที่วาดด้วย Canvas ทีละแบบ ค่า path ของทุกไอคอนอยู่ใน `MODES` และใน markup ของต้นแบบ แปลงเป็น `android:pathData` ได้ตรง ๆ

## 3. การเคลื่อนไหว

ทุกค่าในตารางวัดจากต้นแบบ ค่า easing สองตัวที่ใช้ซ้ำ:

- **ลื่น (EASE):** `PathInterpolator(0.32f, 0.72f, 0f, 1f)` เริ่มเร็วแล้วค่อยหยุด ใช้กับการเลื่อนและชีต
- **เด้ง (SPRING):** `PathInterpolator(0.34f, 1.56f, 0.64f, 1f)` เกินเป้าเล็กน้อยแล้วกลับ ใช้กับการคืนตัวของปุ่มและการขยายขนาด

| เหตุการณ์ | สิ่งที่ขยับ | เวลา | easing |
|---|---|---|---|
| กดปุ่มค้าง | ย่อเหลือ 0.9 | 90ms | ease-out |
| ปล่อยปุ่ม | คืน 1.0 | 220ms | SPRING |
| เปลี่ยนโหมด | แถบเลื่อน + แคปซูลยืดตามชื่อ | 360ms | EASE |
| เลือกระยะซูม | วงกลมขยาย 32→40 | 220ms | SPRING |
| ภาพพรีวิวซูม | `setZoomRatio` ทีละเฟรมผ่าน `animateZoom` เดิม | 320ms | EASE |
| เปลี่ยนสัดส่วนภาพ | ความสูงและตำแหน่งพรีวิว | 380ms | EASE |
| สลับกล้องหน้า/หลัง | ไอคอนหมุน 180° + ภาพเบลอและมืดลงระหว่างสลับ | 420ms / 260ms | EASE |
| ชัตเตอร์ | แสงขาวบนพรีวิวจาง 0.9→0 | 220ms | ease-out |
| ได้ภาพใหม่ | รูปย่อเด้ง 0.4→1.12→1 | 420ms | SPRING |
| เริ่มอัดวิดีโอ | วงแดง 64→สี่เหลี่ยมมน 30 | 260ms | SPRING |
| ข้อความแจ้ง | จางเข้าพร้อมเลื่อนลง 8dp อยู่ 1.5 วินาที | 200ms / 260ms | EASE |
| เปิด/ปิดชีต | เลื่อนขึ้นจากล่าง + พื้นหลังมืด 50% | 460ms / 300ms | EASE |
| แตะโฟกัส | กรอบหดจาก 1.5 เท่า แล้วจางเหลือ 35% | 1100ms | ease-out |

**ลดการเคลื่อนไหว:** เมื่อเปิด `reduce_motion` หรือระบบปิดแอนิเมชัน (`ValueAnimator.areAnimatorsEnabled()` คืน false ใน API 26 ขึ้นไป) ให้ทุกรายการข้างบนใช้เวลา 0 แต่ยังเปลี่ยนสถานะครบ ต้นแบบมีสวิตช์นี้ใน Tweaks

**จุดที่กระตุกที่สุดตอนนี้:** `selectMode` เรียก `bind()` ซึ่ง `unbindAll()` แล้วผูกกล้องใหม่ทุกครั้งที่เปลี่ยนโหมด พรีวิวจึงค้างหรือดำไปชั่วขณะ แก้ได้โดยไม่ต้องเลิก rebind: ก่อน `bind()` ให้เก็บภาพจาก `preview.bitmap` (ใช้ได้เพราะ v0.3 ตั้ง `PreviewView` เป็นโหมด COMPATIBLE ไว้แล้ว) วางเป็น ImageView ทับพรีวิว เบลอด้วย `RenderEffect` บน API 31 ขึ้นไป หรือแค่ลดความสว่างบน API ต่ำกว่านั้น แล้วจางภาพนั้นออก 200ms เมื่อ `previewStreamState` เป็น `STREAMING` วิธีเดียวกันใช้กับการสลับกล้องหน้า/หลังได้ (แถว "สลับกล้อง" ในตาราง) ควรทำข้อนี้ก่อนข้ออื่น เพราะผู้ใช้เห็นทุกครั้งที่เปลี่ยนโหมด

**ไม่ต้องเพิ่ม dependency:** ทุกรายการทำได้ด้วย `ViewPropertyAnimator` / `ValueAnimator` กับ `PathInterpolator` ที่มีตั้งแต่ API 21 ถ้า Codex อยากได้สปริงจริงจาก `androidx.dynamicanimation` ต้องแก้ Gradle ซึ่งเป็นการตัดสินใจของ Codex

**แรงสั่น:** ทำต่อจาก `pressFeedback()` และ detent ใน `StudioUi.kt` ใช้ `CLOCK_TICK` ทุกครั้งที่แถบโหมดผ่านโหมดใหม่และที่ซูมผ่านระยะหลัก ใช้ `KEYBOARD_TAP` ตอนกดชัตเตอร์ เคารพค่า `haptic` เดิม

## 4. กระจกบน Android

minSdk ของแอปคือ 23 แต่การเบลอสิ่งที่อยู่ด้านหลังทำได้จริงเฉพาะบางกรณี จึงแบ่งเป็นสองระดับ

**ปุ่มที่ลอยบนพรีวิว** (แถบบน ซูม แคปซูลโหมด รูปย่อ สลับกล้อง): ไม่ต้องเบลอจริง ใช้ `GradientDrawable` สามชั้น:

1. พื้น `#1E1E20` ทึบ 52%
2. เส้นขอบ 1dp ขาว 14%
3. เส้นสว่างด้านบน 1dp ขาว 14% (`LayerDrawable` ชั้นบนสุด inset ด้านล่าง)

ภาพพรีวิวที่ขยับอยู่ข้างหลังทำให้ดูเป็นกระจกพอแล้ว เหตุที่ไม่เบลอจริงคือ `RenderEffect` (API 31) เบลอได้เฉพาะตัว View เอง ไม่ได้เบลอสิ่งที่อยู่ข้างหลัง และการดึงภาพจาก `PreviewView` มาเบลอทุกเฟรมเปลืองแบตเกินไปสำหรับแอปกล้อง

**ชีตและหน้าต่างลอย** (`studioSheet`, หน้าปรับแต่งโหมด): API 31 ขึ้นไปใช้ `window.setBackgroundBlurRadius(30dp)` กับ `FLAG_BLUR_BEHIND` เพราะระบบเบลอในระดับการวาดหน้าจอ จึงเบลอพรีวิวกล้องข้างหลังได้จริง ให้ตรวจ `WindowManager.isCrossWindowBlurEnabled()` และฟัง listener ของมัน เพราะโหมดประหยัดแบตปิดการเบลอได้ทุกเมื่อ ถ้าเบลอไม่ได้หรือ API ต่ำกว่า 31 ให้ใช้พื้นทึบ 85% แทน

## 5. แถบโหมดที่โหมดที่เลือกอยู่กลางเสมอ

ตอนนี้ทุกครั้งที่เปลี่ยนโหมด `selectMode` เรียก `buildScreen()` ซึ่งสร้าง `modeStrip` ใหม่ทั้งแถบ แถบใหม่จึงเริ่มเลื่อนจากซ้ายสุดทุกครั้ง และ `coerceAtLeast(0)` ใน `StudioUi.kt` ทำให้โหมดแรก ๆ เลื่อนมากลางไม่ได้ ข้อเสนอ:

1. สร้างแถบครั้งเดียวและเก็บไว้ เปลี่ยนเฉพาะสีและน้ำหนักตัวอักษรเมื่อเปลี่ยนโหมด
2. ตั้ง padding ซ้ายขวาของแถว = (ความกว้างจอ − ความกว้างโหมดแรกหรือโหมดสุดท้าย) / 2 เพื่อให้โหมดหัวและท้ายเลื่อนมากลางได้
3. เลือกโหมดแล้วเลื่อนไปที่ `child.left + child.width/2 − scroll.width/2` ด้วย `ObjectAnimator.ofInt(scroll, "scrollX", …)` ใช้ EASE 360ms (`smoothScrollTo` เดิมกำหนด easing ไม่ได้)
4. แคปซูลกระจกเป็น View แยกอยู่ใต้ `HorizontalScrollView` ตรึงอยู่กลางจอ และยืดความกว้างตามโหมดที่เลือกพร้อมกับการเลื่อน
5. เมื่อผู้ใช้ปัดแถบเองแล้วปล่อย ให้หาโหมดที่ใกล้กลางที่สุดแล้วเลือกโหมดนั้น (ดัก `ACTION_UP` และรอให้ fling หยุดก่อน)

**ต้องแก้ด้วย:** การปัดบนพรีวิวใน `CameraActivity` บรรทัดราว 466 ใช้ลิสต์โหมดที่เขียนตายตัว (`NIGHT, PORTRAIT, PHOTO, VIDEO, PRO`) ให้เปลี่ยนไปใช้ลิสต์เดียวกับแถบที่ผู้ใช้ปรับแต่งแล้ว ไม่อย่างนั้นการปัดจะข้ามโหมดที่ผู้ใช้เพิ่มเข้ามา

## 6. ปรับแต่งแถบโหมด

**การเก็บค่า:** `SharedPreferences("camera")` key `mode_bar` เป็นชื่อโหมดคั่นด้วยจุลภาค ค่าเริ่มต้น `NIGHT,PORTRAIT,PHOTO,VIDEO,PRO` ตรงกับแถบปัจจุบัน ชื่อที่อ่านไม่ออก (เช่น เปลี่ยนชื่อ enum ภายหลัง) ให้ข้ามไป ไม่ต้อง crash

**กติกา:**

- ภาพถ่ายต้องอยู่ในแถบเสมอ ลบไม่ได้ (ต้นแบบแสดงไอคอนกุญแจ)
- ในแถบมีได้ไม่เกิน 7 โหมด เกินแล้วแจ้งเตือน
- ถ้าเอาโหมดที่เลือกอยู่ออก ให้กลับไปที่ภาพถ่าย
- `MORE` ไม่อยู่ในแถบอีกต่อไป แทนด้วยปุ่ม "ปรับ" (ไอคอน +) ท้ายแถบเสมอ

**โหมดที่ลากใส่แถบได้:** มีทั้งโหมดภาพใน `PhotoMode` (HDR, Ultra HDR, ความละเอียดสูง, เอกสาร, พาโนรามา) และรายการวิดีโอใน `showMore()` (Time-lapse, Slow-motion, Dual-view, Movie, RAW Video) แบบหลังเปิด Activity อื่น ไม่ได้เปลี่ยน `mode` จึงต้องมีชนิดข้อมูลกลางสำหรับรายการในแถบ เช่น `sealed class BarItem { Photo(mode), Launch(kind) }` เมื่อเลือกรายการแบบ Launch ให้เลื่อนแถบมากลางก่อนแล้วจึงเปิด Activity "คลัง / แต่งคลิป / AI Video" เป็นทางลัด ไม่ใช่โหมด จึงอยู่ในชีตต่อไป ไม่ต้องให้ลากใส่แถบ

**การลาก:** ต้นแบบใช้ HTML drag and drop เพื่อสาธิตเท่านั้น บน Android ให้ใช้กดค้างแล้วลาก:

- **ลากระหว่างสองโซน:** ใช้ `View.startDragAndDrop` (API 24 ขึ้นไป) กับ `OnDragListener` ที่โซน "ในแถบล่าง" และ "โหมดเพิ่มเติม"
- **เรียงในโซนเดียวกัน:** คำนวณตำแหน่งแทรกจากตำแหน่งนิ้วเทียบกับจุดกลางของชิปแต่ละตัว
- **API 23 และผู้ใช้ TalkBack:** ใช้ปุ่ม + และ − บนชิปแทนการลาก (ต้นแบบมีให้แล้ว) ต้องมี `contentDescription` เช่น "เพิ่มHDRลงแถบ" และเพิ่ม accessibility action "เลื่อนไปซ้าย/ขวา" ให้ชิปในแถบ เพราะคนที่ลากไม่ได้ก็ต้องเรียงลำดับได้
- **ขณะลาก:** ชิปที่ถูกลากจาง 35% ช่องที่วางได้ขึ้นเส้นประสีเน้น ชิปที่จะถูกแทรกก่อนหน้าขึ้นกรอบสีเน้น

## 7. แถบบนแสดงเฉพาะสิ่งที่เปิดอยู่

แถบบนไม่ใช่ที่กดปรับค่าอีกต่อไป แต่เป็นที่บอกว่าตอนนี้เปิดอะไรไว้ ช่วยลดความรกของหน้ากล้อง ปุ่มทั้งหมดย้ายไปอยู่ในแผงปัดขึ้น (ข้อ 8)

- **ด้านซ้าย:** ชื่อโหมดและระยะซูม เช่น "ภาพถ่าย · 1×" (ป้าย `currentZoom` เดิม)
- **ด้านขวา:** ไอคอนสีเน้นแบบไม่มีพื้น แสดงเฉพาะสิ่งที่ไม่ใช่ค่าเริ่มต้น เรียงจากซ้ายไปขวาดังนี้
  - แฟลช (เมื่อเปิด หรืออัตโนมัติ ซึ่งมีตัว A กำกับ)
  - ตั้งเวลา (มี 3s / 10s กำกับ)
  - สัดส่วนภาพ เมื่อไม่ใช่ 4:3 (กรอบมุมที่มีตัวเลข 16:9 หรือ 1:1 อยู่ข้างใน)
  - รูปแบบไฟล์ เมื่อไม่ใช่ JPEG (ไอคอนไฟล์ + RAW / AI / RAW+AI)
  - AI อัตโนมัติ เมื่อเปิดและอยู่ในโหมดภาพถ่าย
- **อ่านออกบนฉากสว่าง:** เพราะไม่มีพื้น ให้มีเงาเข้มบาง ๆ ใต้ไอคอนและข้อความ (`TextView.setShadowLayer(2dp, 0, 1dp, #99000000)` และใน VectorDrawable ใส่ path เดิมซ้อนด้านล่างเป็นเส้นดำโปร่ง 40% ที่หนากว่า 1.5 หน่วย)
- **การกด:** แตะไอคอนใดก็ได้เพื่อเปิดแผงตัวเลือก ทั้งแถบต้องมี `contentDescription` รวม เช่น "สิ่งที่เปิดอยู่: แฟลชอัตโนมัติ, สัดส่วนภาพ 16:9"
- **สิ่งที่ต้องเอาออก:** แถว `head` ใน `buildScreen()` (ปุ่ม 4:3, HDR, AI, แฟลช, เมนู) และแถว `outputButtons` (JPEG/RAW/AI/RAW + AI) ย้ายไปอยู่ในแผงทั้งหมด ปุ่ม HDR ไม่ต้องย้าย เพราะเป็นโหมดที่ลากใส่แถบได้แล้ว (ข้อ 6)

## 8. แผงตัวเลือกที่ปัดขึ้นจากแถบล่าง

**บอกให้รู้ว่าปัดได้:** มีลูกศรชี้ขึ้นเล็ก ๆ อยู่เหนือแถบโหมด เด้งขึ้น 4dp ทุก 3.2 วินาที ต้นแบบเด้งไม่หยุด แต่ในแอปให้เด้ง 3 รอบต่อการเปิดแอป และหยุดถาวรเมื่อผู้ใช้เปิดแผงครั้งแรก (เก็บใน prefs เช่น `panel_hint_seen`) แตะลูกศรก็เปิดแผงได้

**ท่าทาง:** พื้นที่แถบโหมดกับแถวชัตเตอร์รับการปัด ดูว่าทิศไหนเด่นกว่า:
- ปัดขึ้นเกิน 36dp เปิดแผง
- ปัดซ้าย/ขวาเกิน 40dp เปลี่ยนโหมด

เมื่อนับเป็นการปัดแล้วต้องกินเหตุการณ์ไว้ ไม่ให้กลายเป็นการแตะชัตเตอร์หรือแตะโหมด ปัดลงที่ขีดบนสุดของแผงหรือแตะพื้นมืดเพื่อปิด

**สิ่งที่อยู่ในแผง ตามลำดับ:**

1. **ถ่ายภาพ:** ปุ่มสี่เหลี่ยม 6 ปุ่ม (แฟลช ตั้งเวลา สัดส่วนภาพ รูปแบบไฟล์ AI อัตโนมัติ เส้นกริด) แต่ละปุ่มมีไอคอน ชื่อ และค่าปัจจุบัน แตะเพื่อวนค่า ปุ่มที่เปิดอยู่เป็นสีเน้นพร้อมพื้นสีเน้นจาง
2. **ปรับแต่งภาพ:** สไตล์สีสำเร็จรูป 6 แบบ (มาตรฐาน สดใส อบอุ่น เย็น ฟิล์ม ขาวดำ) โดยภาพตัวอย่างแสดงผลจริงของแต่ละแบบ แถบเลื่อนความสว่างและความอุ่น −100 ถึง +100 และปุ่มคืนค่า
3. **ปรับแต่งแถบโหมด** (เปิดชีตในข้อ 6)
4. **ตั้งค่าทั้งหมด** อยู่ท้ายสุดเสมอ (ข้อ 10)

ใช้ `studioSheet` เดิมได้ เพราะมีขีดปัดลงเพื่อปิดอยู่แล้ว และใส่การเบลอตามข้อ 4

**ปรับแต่งภาพ: ยังมีเรื่องต้องตัดสินใจ** ต้นแบบเปลี่ยนสีพรีวิวทันที แต่ในแอปต้องตัดสินใจว่า:
- **พรีวิว:** ใน COMPATIBLE mode อาจใช้ `TextureView.setLayerPaint(Paint().apply { colorFilter = ColorMatrixColorFilter(...) })` กับ TextureView ที่อยู่ใน `PreviewView` ต้องทดสอบบนเครื่องจริง
- **ไฟล์ที่บันทึก:** ใช้ ColorMatrix เดียวกันใน `PhotoEffects` ตอนบันทึก
- **ขอบเขต:** ไม่ใส่ให้ DNG ต้องตกลงกับ Ogay ว่าภาพต้นฉบับใน Luma จะใส่โทนนี้หรือเก็บแยกเป็นการแก้ภายหลัง ถ้าใส่ สำเนา AI ต้องได้โทนเดียวกัน และควรบันทึกชื่อโทนลงฐานข้อมูลเพื่อให้แกลเลอรีแสดงได้

## 9. ปรับค่าแบบโปร สำหรับภาพและวิดีโอ

**ที่ใช้:** โหมดโปร และวิดีโอโปร (รายการ "Movie / PRO Video" เดิม ซึ่งในต้นแบบเรียกว่า "วิดีโอโปร" และลากใส่แถบได้)

**แถวชิป:** แถวกระจกเหนือปุ่มซูม มี ISO ชัตเตอร์ สมดุลแสงขาว โฟกัส และชดเชยแสง วิดีโอโปรมีชิปของวิดีโอทั้งชุดต่อท้าย (ข้อ 13) ชิปที่ตั้งเป็นค่ามือเปลี่ยนตัวเลขเป็นสีเน้น

**แผงหมุนปรับค่า:** แตะชิปเพื่อเปิดแผงเหนือแถว ในแผงมีชื่อค่า ตัวเลขปัจจุบันตัวใหญ่ ปุ่ม AUTO และแถบเลื่อน ระหว่างที่แผงเปิด ปุ่มซูมซ่อนไว้ แตะบนภาพหรือแตะชิปเดิมเพื่อปิด ต้นแบบใช้แถบเลื่อนธรรมดา ส่วนในแอปแนะนำไม้บรรทัดเลื่อนแนวนอนที่สั่นทุกขีด

**ค่าที่ใช้:** ใช้รายการค่าจาก `ManualControls.kt` เดิม (ISO, ชัตเตอร์ 1/8000–1s, แดด/เมฆ/หลอดไฟ/ฟลูออเรสเซนต์, โฟกัสมือ ∞ → ใกล้, EV) ส่วนนี้เปลี่ยนเฉพาะหน้าตา ไม่ต้องแก้การสั่งกล้องผ่าน Camera2Interop

**กติกาที่ต้นแบบยังไม่ได้ทำ แต่แอปต้องมี:**
- ถ้า ISO และชัตเตอร์เป็นค่ามือทั้งคู่ ชิป EV ต้องจางและกดไม่ได้ พร้อมข้อความ "EV ใช้เมื่อ ISO อยู่ AUTO" ตามโค้ดเดิม
- ถ้ากล้องไม่เปิด manual sensor ให้ซ่อนชิปที่ใช้ไม่ได้ และแสดงข้อความเดิม "กล้องนี้ไม่เปิด Manual sensor ให้แอป"
- แถวชิปแทนปุ่ม "ISO · S · WB · AF · EV" (`aux`) ที่ตอนนี้เปิดชีตแยก

## 10. หน้าตั้งค่า

- **รายการ:** ใช้ key เดิมทั้งหมดจาก `StudioSettings.kt` และ `CaptureSettings.kt` ไม่เพิ่มหรือเปลี่ยนชื่อ key เพื่อให้ค่าที่ผู้ใช้ตั้งไว้แล้วยังอยู่
- **กลุ่ม:** ภาพและ AI · ช่วยถ่าย · เสียงและการสั่น · การแสดงผล · เซลฟี่ · ข้อมูลในภาพ · เกี่ยวกับ
- **หน้าตา:** แต่ละแถวมีไอคอนในสี่เหลี่ยมมนสีอ่อนตามกลุ่ม และมีคำอธิบายใต้ชื่อสำหรับรายการที่ต้องอธิบาย เช่น GPS กับลดการเคลื่อนไหว
- **ช่องค้นหา:** ด้านบน กรองจากชื่อ คำอธิบาย และชื่อกลุ่ม
- **ตัวควบคุม:** สวิตช์มีความหมายเป็น `Switch` สำหรับ TalkBack จำนวนเฟรม AI เป็นปุ่มแบ่งช่อง 4/8/16/32 รูปแบบไฟล์เริ่มต้นกับแถบโหมดเป็นแถวที่เปิดหน้าย่อย
- **เปิดเป็นหน้าเต็ม:** แนะนำให้เปลี่ยนจาก dialog ที่ `showStudioSettings` ใช้อยู่เป็น Activity ใหม่ เพราะรายการยาวเกินกว่าจะใส่ dialog ได้ดี (ไฟล์ Activity เป็นของ Codex) เมื่อกลับจากหน้าตั้งค่า กล้องจะ bind ใหม่ ให้ใช้ภาพค้างเบลอตามข้อ 3

## 11. แกลเลอรี: ภาพในแอปและทั้งเครื่อง

**แท็บ "ใน Luma":** แหล่งข้อมูลคือ `Shots` กับ `MediaLedger` มีหมวด ทั้งหมด · AI · RAW · HDR · พาโนรามา · เอกสาร · วิดีโอ ป้ายบนรูปย่อบอกชนิดของรูป

ตอนนี้แยกหมวดจากข้อมูลเดิมได้บางส่วน:
- AI = มี `ai`
- RAW = มี `raw` หรือ `output` เป็น RAW/BOTH

แต่ HDR พาโนรามา เอกสาร และวิดีโอ ปนอยู่ใน `MediaLedger` ในรูปข้อความชื่อ (เช่น "Panorama · ORB / homography") ซึ่งแยกได้ไม่แน่นอน จึงแนะนำให้เพิ่มฟิลด์หมวดที่ชัดเจนใน `MediaLedger` (การแก้ฐานข้อมูลเป็นของ Codex)

**แท็บ "ทั้งเครื่อง":** อ่านจาก MediaStore ทั้งภาพและวิดีโอ
- **อัลบั้ม:** จัดตาม `BUCKET_DISPLAY_NAME` เป็นแถวการ์ดที่เลื่อนแนวนอน แตะเพื่อกรอง
- **ลำดับ:** เรียงตาม `DATE_TAKEN` ใหม่สุดก่อน
- **โหลดทีละหน้า:** หน้าละประมาณ 120 รายการ
- **รูปย่อ:** ใช้ `PhotoMedia.thumbnail` เดิม
- **ป้าย:** รูปที่ Luma ถ่ายในแท็บนี้มีป้ายเหมือนแท็บแรก

**สิทธิ์ (manifest เป็นของ Codex):**
- **API 33 ขึ้นไป:** `READ_MEDIA_IMAGES` และ `READ_MEDIA_VIDEO`
- **API 34 ขึ้นไป:** เพิ่ม `READ_MEDIA_VISUAL_USER_SELECTED` เพื่อรองรับกรณีผู้ใช้เลือกให้เข้าถึงแค่บางรูป
- **API 32 ลงไป:** `READ_EXTERNAL_STORAGE` โดยตั้ง `maxSdkVersion="32"`
- **จังหวะขอสิทธิ์:** ขอเมื่อผู้ใช้เปิดแท็บ "ทั้งเครื่อง" ครั้งแรกเท่านั้น ไม่ขอตอนเปิดแอป รูปที่แอปถ่ายเองบน API 29 ขึ้นไปอ่านได้โดยไม่ต้องขอสิทธิ์ แท็บแรกจึงใช้ได้เสมอ
- **ได้สิทธิ์บางรูป:** แสดงแถบแจ้งพร้อมปุ่ม "เลือกรูปเพิ่ม" (ขอสิทธิ์อีกครั้งเพื่อเปิดหน้าต่างเลือกรูปของระบบ) และ "อนุญาตทั้งหมด" (ถ้าถูกปฏิเสธถาวรแล้ว ให้เปิดหน้าตั้งค่าแอป)
- **ตรวจซ้ำ:** ตรวจสิทธิ์ใหม่ทุก `onResume` เพราะผู้ใช้เปลี่ยนสิทธิ์จากหน้าตั้งค่าระบบได้

**ถ้าจะลง Google Play:** นโยบายสิทธิ์รูปและวิดีโอของ Play จำกัด `READ_MEDIA_IMAGES/VIDEO` ไว้สำหรับแอปที่ต้องเข้าถึงรูปทั้งหมดเป็นหน้าที่หลัก ส่วนแอปอื่นต้องใช้ photo picker ของระบบ ตอนนี้แจก APK ผ่าน GitHub Actions จึงยังไม่กระทบ แต่ควรตรวจนโยบายล่าสุดก่อนตัดสินใจลง Play

**ตัวดูรูป:** เปิดแบบขยายออกจากรูปย่อ ด้านบนมีปุ่มปิดกับปุ่มแชร์ ด้านล่างมีปุ่มสลับต้นฉบับ/ภาพ AI (เฉพาะรูปที่มีสำเนา AI) และปุ่มข้อมูล ใช้ `InspectView` เดิมสำหรับการบีบซูม

## 12. รอบที่ 3: เมนูกระจก วงล้อซูม วิดีโอ โปร และกระจกเด้งตามนิ้ว

**เมนูแบบเลื่อนลงที่เป็นกระจก (dropdown):** ตัวเลือกที่มีหลายค่าใช้เมนูกระจกแบบเดียวกันทุกที่ ไม่ใช้การแตะวนค่าอีกต่อไป
- **หน้ากล้อง:** แฟลช ตั้งเวลา สัดส่วนภาพ รูปแบบไฟล์ ความละเอียดวิดีโอ fps กันสั่น HDR วิดีโอ เสียง
- **หน้าตั้งค่า:** รูปแบบไฟล์เริ่มต้น จำนวนเฟรม AI สัดส่วนภาพเริ่มต้น

หน้าตาของเมนู:
- **ตัวเมนู:** พื้นกระจกเข้ม 78–80% มุม 22dp มีหัวเรื่องเล็กด้านบน
- **แต่ละรายการ:** สูง 48dp มีไอคอน ชื่อ คำอธิบายสั้น (ถ้ามี) และเครื่องหมายถูกที่ค่าปัจจุบัน
- **ตำแหน่ง:** เปิดใต้ปุ่มที่กด ถ้าที่ไม่พอให้เปิดขึ้นด้านบน
- **ตอนเปิด:** ขยายจากจุดที่อยู่ตรงปุ่ม 0.86→1 พร้อมจางเข้าและหายเบลอ ใช้เวลา 380ms ด้วยเส้นโค้ง `PathInterpolator(0.2f, 0.9f, 0.25f, 1.15f)` ที่เกินเป้าเล็กน้อย
- **หลังเลือก:** ปิดเองหลังเลือก 140ms เพื่อให้เห็นเครื่องหมายถูกย้ายก่อน

บน Android ใช้ `PopupWindow` ที่ตั้ง `setBackgroundBlurRadius` บน API 31 ขึ้นไป ใช้ `ListPopupWindow` ไม่ได้ เพราะคุมแอนิเมชันกับพื้นหลังได้น้อยเกินไป

**ปุ่มสัดส่วนภาพในแผงตัวเลือก:** เปิดเมนูเดียวกัน มีคำอธิบายแต่ละสัดส่วน (เต็มเซนเซอร์ / จัตุรัส / ครอปบนล่าง)

**สไตล์สีในแผงตัวเลือก:** เลิกใช้วงสีเหลือง เพราะเงาวงถูกตัดที่ขอบบนของแถวเลื่อน แบบใหม่เป็นกรอบขาวทึบ 3dp อยู่ในขนาดปุ่มเอง ไม่ล้นออกนอกปุ่ม มีวงถูกสีขาวที่มุมขวาล่าง และชื่อสไตล์ตัวหนา แถวเลื่อนต้องมี padding บนล่างอย่างน้อย 8dp

**เอาป้าย "ภาพถ่าย · 1×" ออก:** แถบบนเหลือเฉพาะไอคอนสิ่งที่เปิดอยู่ ชิดขวา

**วงล้อซูม:**
- **เปิดวงล้อ:** แตะปุ่มระยะซูมเพื่อกระโดดไประยะนั้นทันที ถ้าลากปุ่มซูมซ้าย/ขวาเกิน 6dp ปุ่มจะจางหาย แล้ววงล้อครึ่งวงกลมแบบกระจกโผล่ขึ้นมาแทน (ขยาย 0.94→1 ใน 420ms)
- **ขีดบนวงล้อ:** ขีดละเอียดห่างกัน 1/14 stop ขีดหนาพร้อมตัวเลขอยู่ที่ระยะของเลนส์ ตรงกลางมีเส้นสีเน้นชี้ค่าปัจจุบัน ค่าซูมแสดงในป้ายกระจกด้านบน
- **ความเร็วในการหมุน:** ลาก 95dp = 1 stop (ซูมเพิ่ม/ลดเท่าตัว) ลากซ้ายเพื่อซูมเข้า เป็นทิศเดียวกับวงล้อของ iPhone
- **ล็อกเบา ๆ ที่เลนส์:** เมื่อเข้าใกล้ระยะของเลนส์ในช่วง ±0.075 stop จะดูดค่าไปที่เลนส์นั้นพอดี ให้สั่น `CLOCK_TICK` ครั้งเดียวตอนเข้าช่วง
- **ระยะที่รองรับ:** ระยะของเลนส์ต้องมาจากเครื่องจริง ต้นแบบใช้ 0.6 / 1 / 2 / 3.5 ตามที่คาดไว้สำหรับ Reno15 แต่ในแอปให้หาจาก `zoomState.minZoomRatio` และ Physical camera ID ที่ `FrameMetadata` อ่านได้ ระยะ 2× เป็นการครอปจากกล้องหลัก จะล็อกที่ 2× ด้วยหรือไม่ต้องรอผลวัดจริง ช่วงทั้งหมดใช้ `minZoomRatio`–`maxZoomRatio` ต้นแบบใช้ 10×
- **ระหว่างลาก:** เรียก `setZoomRatio` ต่อเนื่องโดยไม่ต้องรอแอนิเมชัน 320ms ในข้อ 3
- **ปิดวงล้อ:** ปล่อยนิ้วแล้ว 1.3 วินาที วงล้อจะหายและปุ่มซูมกลับมา ปุ่มที่ไฮไลต์คือเลนส์ล่าสุดที่ไม่เกินค่าซูมปัจจุบัน และแสดงค่าจริง เช่น 2.6×

**ตัวเลือกวิดีโอ:** ทุกโหมดวิดีโอมีแถวชิปกระจกเหนือปุ่มซูม แต่ละชิปเปิดแผงปรับค่าแบบเดียวกับโปร ไม่ใช้เมนู (ข้อ 13) ชิปที่มีขึ้นกับโหมด:

| โหมด | ชิป |
|---|---|
| วิดีโอ | ความละเอียด (720p/1080p/4K) · fps (24/30/60) · กันสั่น (ปิด/มาตรฐาน/แอ็กชัน) · HDR (ปิด/HLG 10 บิต) · เสียง (สเตอริโอ/โมโน/ลดเสียงลม) |
| Slow-motion | ความละเอียด · fps (120/240) · เสียง |
| Time-lapse | ความละเอียด · ช่วงถ่าย (0.5/1/2 วินาที) · กันสั่น |
| Dual-view, RAW Video | ความละเอียด · fps · เสียง |
| วิดีโอโปร | ISO · ชัตเตอร์ · WB · โฟกัส · EV ตามด้วยชิปทั้ง 5 ของวิดีโอ (ข้อ 13) |

แถบบนแสดงความละเอียดกับ fps ที่ใช้อยู่เสมอเมื่ออยู่ในโหมดวิดีโอ ต้องแสดงเฉพาะค่าที่กล้องรองรับจริง เช่น 4K60 ต้องเช็กจาก `QualitySelector` / `Recorder.getVideoCapabilities` ก่อน ค่าที่ใช้ไม่ได้ให้ซ่อน ไม่ใช่แค่ทำให้จาง

**ชิปโปรเรียงใหม่และแถบเลื่อนไล่สี:**
- **เลื่อนมาหน้าสุด:** แตะชิปใด ชิปนั้นจะเลื่อนไปอยู่หน้าสุดของแถว ชิปอื่นเลื่อนตามไปทางขวา (เลื่อน `x` ด้วยสปริง 460ms ชิปทุกตัวกว้างเท่ากันจึงคำนวณตำแหน่งได้ตรง) แผงปรับค่าขยายออกจากตำแหน่งชิป
- **สีไล่ระดับ:** แถบเลื่อนเป็นสีไล่ตามความหมายของค่า

| ค่า | สีไล่ |
|---|---|
| ISO 50→6400 | ฟ้า → เขียวมิ้นต์ → เหลือง → ส้ม → แดง (ยิ่งสูง นอยส์ยิ่งมาก) |
| ชัตเตอร์ | ฟ้า → ม่วง → เหลือง → ส้ม (ยิ่งช้า ยิ่งเสี่ยงสั่น) |
| WB 2800K→7500K | ส้มอุ่น → ขาว → ฟ้า |
| EV | เทาเข้ม → ขาว |

- **ส่วนที่เลือกแล้ว:** ส่วนที่อยู่ซ้ายของปุ่มเลื่อนแสดงสีเข้ม (ตั้ง `background-size` ให้สีไล่กินความกว้างเต็มแถบ สีจึงไม่หดตาม) ส่วนที่เหลือจาง 28%
- **ปุ่มเลื่อน:** มีวงและแสงเรืองเป็นสีตรงตำแหน่งนั้น ตัวเลขค่าในชิปและในแผงก็เป็นสีเดียวกัน
- **หาง:** เมื่อลากเร็ว มีแถบเรืองเบลอเป็นหางอยู่ด้านหลังปุ่มเลื่อน ความยาวหาง = ความเร็วการลาก × 7 (สูงสุด 150dp) และหดกลับเป็น 0 ใน 520ms หลังหยุดลาก 70ms บน Android วาดเป็น `LinearGradient` + `BlurMaskFilter` ใน `onDraw` ของ View แถบเลื่อนเอง
- **ปล่อยนิ้ว:** ดูดเข้าค่าที่ใกล้ที่สุดด้วยสปริง 300ms ค่าเป็นขั้นตาม `ManualControls.kt` จึงมีขีดเล็กใต้แถบทุกค่า

**กระจกเด้งตามนิ้ว:** ปุ่มกระจกทุกตัวตอบสนองต่อนิ้วที่จุดสัมผัส
- **ตอนกด:** ปุ่มขยาย 1.05–1.06 เท่า และเลื่อนเข้าหานิ้วไม่เกิน 10% ของขนาด (สูงสุด 12dp แนวนอน 9dp แนวตั้ง) มีแสงขาวโปร่ง 30% วงกลมรัศมี 110dp ตามตำแหน่งนิ้ว
- **ตอนลากนิ้วบนปุ่ม:** ปุ่มกับแสงตามนิ้วไปด้วย
- **ตอนปล่อย:** เด้งกลับด้วยสปริง 560ms (`PathInterpolator(0.34f, 1.56f, 0.64f, 1f)`) แสงจางออก 480ms
- **บน Android:** ทำเป็น `OnTouchListener` กลางใน `Ui.kt` ต่อจาก `pressFeedback()` ใช้ `translationX/Y` + `scaleX/Y` ส่วนแสงใช้ `RippleDrawable` แบบ `RADIUS_AUTO` ที่ตั้ง hotspot ตามนิ้ว (`drawableHotspotChanged`) หรือวาด `RadialGradient` เอง
- **ลดการเคลื่อนไหว:** เมื่อเปิด ให้ปิดทั้งการเลื่อนและการขยาย เหลือแค่แสง

## 13. รอบที่ 4: ปรับแสงที่ขอบซ้าย โฟกัสมือที่ขอบขวา เมนูลากเลือก และแผงปรับค่าแบบเดียว

**ปรับความสว่างที่ขอบซ้าย:**
- **ตอนพัก:** แถบกระจกแนวตั้งสูง 240dp ซ่อนอยู่นอกขอบซ้าย เห็นแค่ขอบ 6dp จาง 50% เป็นใบ้ว่ามีอยู่ ถ้าค่าไม่ใช่ 0 ขอบที่เห็นจะชัดขึ้น (85%)
- **ตอนปรับ:** ปัดขึ้น/ลงบนภาพในครึ่งซ้ายหรือตรงกลาง แถบจะเลื่อนออกมา ปุ่มเลื่อนเป็นวงกลมขาวมีรูปดวงอาทิตย์ แถบสีเน้นยืดจากขีดกลาง (0) ไปถึงปุ่มเลื่อน ข้างแถบมีป้ายค่า เช่น +1.3 ปัด 90dp = 2 EV
- **ภาพพรีวิว:** เปลี่ยนตามค่าทันทีระหว่างลาก
- **ซ่อนเอง:** หลังปล่อยนิ้ว 1.6 วินาที

**แตะโฟกัสใหม่ล้างค่าความสว่าง:**
- แตะโฟกัสใหม่จะคืนค่าความสว่างเป็น 0 และแจ้งว่า "ล้างค่าความสว่างแล้ว"
- ถ้ากดปุ่มล็อก (กุญแจเหนือแถบ) ไว้ ค่าจะไม่ถูกล้าง และแถบบนแสดงไอคอนกุญแจกับ "AE"
- ปุ่มล็อกโผล่พร้อมแถบ และค้างอยู่ตลอดเวลาที่ล็อก

**บน Android ฝั่งความสว่าง:**
- ใช้ `CameraControl.setExposureCompensationIndex` ช่วงและขนาดขั้นอ่านจาก `cameraInfo.exposureState` ปกติขั้นละ 1/3 หรือ 1/6 EV จึงต้องปัดค่าให้ตรงขั้นก่อนแสดง
- การล็อกใช้ `CONTROL_AE_LOCK` ผ่าน Camera2Interop ร่วมกับ `FocusMeteringAction` ที่ `disableAutoCancel()`
- สั่น `CLOCK_TICK` เมื่อผ่าน 0

**โฟกัสมือที่ขอบขวา:**
- **หน้าตา:** แถบแบบเดียวกันที่ขอบขวา ด้านบนเป็นรูปภูเขา (∞) ด้านล่างเป็นรูปดอกไม้ (ใกล้) ปุ่มเลื่อนเป็นวงแหวนสีฟ้าแยกจากสีเน้นของความสว่าง ป้ายบอกระยะ เช่น "MF 69 ซม." ตอนยังไม่ปรับเขียนว่า "AF"
- **การปรับ:** ปัดขึ้น/ลงบนภาพในส่วนขวา (เริ่มเกิน 70% ของความกว้าง) ภาพเบลอตามระยะ ในต้นแบบป้ายร้านอยู่ราว 2 เมตร จึงคมที่สุดเมื่อตั้งระยะใกล้ 2 เมตร
- **คืนเป็น AF:** แตะโฟกัสใหม่
- **บน Android:** ตั้ง `CONTROL_AF_MODE_OFF` + `LENS_FOCUS_DISTANCE` (หน่วยไดออปเตอร์ 0 = ∞ สูงสุดคือ `LENS_INFO_MINIMUM_FOCUS_DISTANCE`) ให้ตำแหน่งบนแถบเป็นเส้นตรงตามไดออปเตอร์ ระยะที่แสดง = 1/ไดออปเตอร์ (เมตร) ถ้ากล้องไม่มี `MANUAL_SENSOR` ให้ซ่อนแถบขวาทั้งแถบ

**แยกท่าทางบนภาพ:** เมื่อนิ้วขยับเกิน 10dp ให้ดูว่าทิศไหนเด่นกว่า
- แนวตั้ง: ปรับความสว่าง หรือโฟกัสมือถ้าเริ่มในส่วนขวา
- แนวนอน: เปลี่ยนโหมด
- ขยับไม่ถึง: นับเป็นการแตะโฟกัส

**เมนูลากเลือก:**
- **การเลือก:** ทุกเมนูกระจก (หน้ากล้องและหน้าตั้งค่า) กดค้างแล้วลากขึ้นลงได้ แถบไฮไลต์กระจกเลื่อนตามรายการที่อยู่ใต้นิ้ว ปล่อยนิ้วเพื่อเลือก ใช้เมาส์ชี้ก็ไฮไลต์ตามได้
- **ขนาด:** ทุกรายการสูงเท่ากัน 52dp ห่างกัน 2dp จะได้คำนวณรายการจากตำแหน่งนิ้วได้ตรง
- **ไฮไลต์:** เลื่อนด้วยสปริง 240ms ขณะกดอยู่ทั้งไฮไลต์และรายการขยาย 1.02–1.03 เท่า
- **บน Android:** ดัก `onTouch` ของ `PopupWindow` เลื่อน View ไฮไลต์ด้วย `translationY` สั่น `CLOCK_TICK` ทุกครั้งที่ไฮไลต์เปลี่ยนรายการ เลือกเมื่อ `ACTION_UP`

**วงล้อซูมไม่ลอย:** ไล่ความทึบของวงล้อจากทึบเต็มที่ 40% บนไปจนใสหมดที่ขอบล่าง (alpha mask) วงล้อจึงกลืนไปกับภาพที่ขอบล่างของพรีวิว บน Android วาดใน `saveLayer` แล้วใช้ `LinearGradient` กับ `PorterDuff.Mode.DST_IN`

**แผงปรับค่าแบบเดียวทุกค่า:**
- **รูปแบบเดียว:** ทั้งค่าโปรและค่าวิดีโอใช้แผงเดียวกัน คือชื่อ ค่าตัวใหญ่ ปุ่มคืนค่า แถบเลื่อนไล่สีมีหาง และขีดใต้แถบ
- **ปุ่มคืนค่า:** ค่าที่มีโหมดอัตโนมัติ (ISO ชัตเตอร์ WB โฟกัส) ใช้คำว่า "AUTO" ค่าที่เป็นตัวเลือก (ความละเอียด fps กันสั่น HDR เสียง) ใช้ "ค่าเริ่มต้น"
- **สีไล่ของวิดีโอ:**

| ค่า | สีไล่ |
|---|---|
| ความละเอียด 720p→4K | เทา → ฟ้า → ม่วง |
| fps 24→60 | เหลือง → เขียว → ฟ้า |
| กันสั่น | เทา → เขียว → เหลือง |

- **วิดีโอโปร:** มี 10 ชิป (ISO ชัตเตอร์ WB โฟกัส EV ความละเอียด fps กันสั่น HDR เสียง) ชิปกว้าง 64dp เท่ากัน และแถวเลื่อนแนวนอนได้ แตะชิปแล้วชิปนั้นเลื่อนไปหน้าสุด และแถวเลื่อนกลับไปต้นแถวเอง
- **ชั้นการแสดงผล:** แผงปรับค่าอยู่ชั้นบนกว่าแถวชิป และห่างแถวชิป 12dp ไม่ทับกันแล้ว

**แกลเลอรี:**
- เนื้อหาเริ่มต่ำกว่าแถบบน 230dp ไม่ติดกันแล้ว
- กรอบอัลบั้มที่เลือกเป็นเส้นขอบด้านในการ์ด จึงไม่ถูกตัด

## 14. รอบที่ 5: แถบโหมดลากต่อเนื่อง ล็อก AE/AF แอนิเมชันหยดน้ำ แถบเลื่อนยืดหยุ่น ภาพย่อเลนส์ และแกลเลอรี

**แถบโหมดลากได้ต่อเนื่อง** (แทนข้อ 5 เรื่องการปัดทีละโหมด):
- **ระหว่างลาก:** ลากแนวนอนที่ไหนก็ได้ในส่วนล่าง (แถบโหมดหรือแถวชัตเตอร์) แถบเลื่อนตามนิ้วทันที เลยโหมดหัวหรือท้ายได้แต่มีแรงต้าน 35% (rubber band) กรอบกระจกตรงกลางเปลี่ยนความกว้างตามโหมดที่อยู่ใต้กลางจอระหว่างลาก
- **ปล่อยนิ้ว:** คำนวณตำแหน่งสุดท้ายจาก ระยะลาก + ความเร็ว × 160ms แล้วดีดเข้าโหมดที่ใกล้ที่สุดด้วยสปริง 420ms ลากเร็วจึงข้ามหลายโหมดได้ในครั้งเดียว
- **บน Android:** ใช้ `OverScroller.fling` หรือ `FlingAnimation` (dynamicanimation) แล้วจบที่จุดกลางของโหมดที่ใกล้ที่สุด สั่น `CLOCK_TICK` ทุกครั้งที่โหมดผ่านกลางจอ

**แตะค้างเพื่อล็อก AE/AF:**
- **ล็อก:** กดค้างบนภาพ 550ms โดยไม่ขยับ จะโฟกัสและล็อกทั้งแสงและโฟกัสที่จุดนั้น กรอบโฟกัสหนาขึ้นและเต้นสองจังหวะแล้วค้างไว้ ด้านบนขึ้นป้ายกระจก "ล็อก AE/AF" ส่วนแถบบนขวาขึ้น "AE"
- **ปรับแสงต่อ:** ยังไม่ปล่อยนิ้วก็ลากขึ้นลงเพื่อปรับความสว่างต่อได้ทันที ใช้แถบที่ขอบซ้ายตัวเดิม (ข้อ 13) ซึ่งเลื่อนออกมาตอนล็อก
- **ปลดล็อก:** แตะครั้งเดียวที่ไหนก็ได้ จะปลดล็อกและคืนความสว่างเป็น 0
- **ปุ่มกุญแจข้างแถบ:** ยังใช้ล็อกแค่แสงได้เหมือนเดิม
- **บน Android:** `FocusMeteringAction.Builder(point, FLAG_AF or FLAG_AE).disableAutoCancel()` ร่วมกับ `CONTROL_AE_LOCK = true` ผ่าน Camera2Interop สั่น `LONG_PRESS` ตอนล็อก

**แอนิเมชันหยดน้ำแบบชิ้นเดียว (ใช้กับทุก element ที่เปิด/ปิด):** รุ่นก่อนใช้หยดน้ำกับแผงเป็นคนละชิ้น จึงดูเป็นสองแอนิเมชันที่ไม่ต่อกัน รุ่นนี้ให้ตัวแผงเองเป็นหยดน้ำแล้วยืดออก เป็น View เดียวตั้งแต่ต้นจนจบ

- **แผงตัวเลือกและชีตปรับแถบโหมด (ยืดแบบชีต 720ms):** ใช้จุดยึด (pivot) ที่ลูกศรหรือปุ่ม "ปรับ" แล้ว
  - เริ่มเป็นวงกลม 52dp (`scaleX` 0.14, `scaleY` 0.066, มุมโค้งเต็ม)
  - ยืดเป็นหยดรี (0.6 × 0.38, มุม 140dp)
  - เกินเป้าเล็กน้อย (1.035 × 0.965) แล้วเด้งกลับ (0.99 × 1.012)
  - จบที่ 1 × 1 มุม 34dp
- **ตอนปิด (440ms):** ย้อนเส้นทางเดิม แผงหดกลับเป็นหยดแล้วจมลงที่ลูกศรเหนือแถบโหมด ถ้าปิดด้วยการปัดลง หยดจะเริ่มจากตำแหน่งที่นิ้วลากค้างไว้ (`--dy`) จึงต่อจากการลากโดยไม่กระโดด
- **เนื้อหาข้างใน:** จาง เบลอ และเลื่อนขึ้น 10dp เข้ามาหลังตัวแผงยืดไปแล้ว 32% และจางออกภายใน 160ms ตอนปิด ข้อความจึงไม่ถูกบีบให้เห็นระหว่างยืด
- **เมนูกระจก แผงปรับค่าโปร/วิดีโอ ป้ายแจ้ง ป้ายล็อก AE/AF และภาพย่อเลนส์ (ยืดแบบป๊อป 560ms):** ใช้จุดยึดที่ปุ่มหรือชิปที่กด
  - เริ่มจาก 0.22 × 0.14 มุมโค้งเต็ม เบลอ 6dp
  - ไปถึง 1.05 × 0.95 แล้ว 0.985 × 1.02 ก่อนจบที่ 1
  - ตอนปิดหดกลับเข้าจุดเดิม (300ms)
  - แตะชิปโปรตัวอื่นขณะแผงเปิดอยู่ แผงจะป๊อปใหม่จากชิปนั้น
- **ตัวดูรูปในแกลเลอรี (620ms):** ใช้จุดยึดที่รูปย่อที่แตะ มุมโค้งลดจาก 60dp เหลือ 0 ตอนเต็มจอ
- **บน Android:**
  - ใช้ `scaleX/scaleY` ของ View เดียวผ่าน `ObjectAnimator` + `PropertyValuesHolder.ofKeyframe` (คีย์เฟรมตามข้างบน) ตั้ง `pivotX/pivotY` ที่ปุ่มต้นทาง
  - มุมโค้งใช้ `ValueAnimator` ที่ปรับ `GradientDrawable.cornerRadius` (หรือ `ShapeAppearanceModel` ถ้ามี Material) ตั้งเวลาให้ตรงกับคีย์เฟรมเดียวกัน
  - เนื้อหาเป็น View ลูกที่ตั้ง `alpha` และ `translationY` แยก ให้หน่วงเข้าตามข้างบน
  - ห้ามใช้ `createCircularReveal` ร่วมกับหยดน้ำแยกอีกชิ้น เพราะจะกลับไปมีปัญหาเดิม
- **ลดการเคลื่อนไหว:** เมื่อเปิด ทุกอย่างข้างบนข้ามไปที่สถานะสุดท้ายทันที

**แถบเลื่อนยืดหยุ่น** (ทุกแผงปรับค่า ทั้งโปรและวิดีโอ):
- **ตอนกด:** ปุ่มเลื่อนขยาย 1.14 เท่า วงสีและแสงเรืองใหญ่ขึ้น
- **ตอนลาก:** ปุ่มยืดตามความเร็ว (กว้าง × ไม่เกิน 1.7 และสูง ÷ √ค่านั้น ปริมาตรจึงดูคงเดิม)
- **ลากเลยปลายแถบ:** ปุ่มกับแถบสีเลยออกไปได้ไม่เกิน 24dp แบบหน่วงมากขึ้นเรื่อย ๆ (`24 × (1 − e^(−ระยะ/60))`)
- **ปล่อยนิ้ว:** ทุกอย่างเด้งกลับด้วยสปริง 420ms

**ภาพย่อเลนส์เมื่อซูมเกิน 10×:**
- **ช่วงซูม:** ต้นแบบซูมได้ถึง 30× ในแอปใช้ `maxZoomRatio` จริง
- **ภาพย่อ:** เกิน 10× จะมีการ์ดกระจก 98×130dp ที่มุมขวาบน ขยายเด้งเข้ามา ข้างในแสดงภาพเต็มของเลนส์ที่ใช้อยู่ (3.5× ถ้าซูมตั้งแต่ 3.5× ขึ้นไป ไม่อย่างนั้น 1×) พร้อมกรอบสีเน้นบอกส่วนที่ซูมอยู่ นอกกรอบมืดลง 38% มุมล่างบอกชื่อเลนส์
- **บน Android:** ห้ามเปิดกล้องตัวที่สอง ให้ครอปจากเฟรมเดียวกันแทน คือดึงภาพเต็มของเลนส์ปัจจุบันจาก `ImageAnalysis` ความละเอียดต่ำ หรือใช้ `preview.bitmap` ก่อนซูมเกิน 10× ซึ่งค้างไว้เป็นภาพนิ่งก็ได้ เพราะใช้แค่บอกตำแหน่ง

**กระจกเด้งตามนิ้วไม่ขัดการเลื่อน:** ถ้านิ้วขยับเกิน 10–12dp หลังกด ให้ปล่อยเอฟเฟกต์กระจกทันที เพื่อไม่ให้ปุ่มขยายหรือเลื่อนตามนิ้วตอนผู้ใช้กำลังเลื่อนแถว ปัญหาภาพในแถบอัลบั้มขาดตอนลากเกิดจากตรงนี้ แถวอัลบั้มต้องมี padding บนล่าง 8dp เผื่อการขยาย และใช้ snap แบบ proximity

**แกลเลอรี: กดค้างดูตัวอย่าง:**
- **เปิด:** กดค้างที่รูปย่อ 420ms การ์ดกระจกจะขยายจากตำแหน่งรูปย่อไปเป็นภาพใหญ่กลางจอ (480ms เกินเป้าเล็กน้อย) พื้นหลังเบลอ 18dp และมืดลง
- **ดูรูปถัดไป:** ไม่ต้องปล่อยนิ้ว ลากซ้ายขวาเกิน 70dp เพื่อเปลี่ยนรูป รูปแรกและรูปสุดท้ายมีแรงต้านที่ขอบ
- **ปิด:** ปล่อยนิ้วแล้วการ์ดหดกลับไปที่รูปย่อ ส่วนการแตะสั้นยังเปิดตัวดูรูปเต็มเหมือนเดิม
- **บน Android:** ใช้ shared element transition หรือคำนวณ `scaleX/Y` + `translationX/Y` จาก `getLocationInWindow` ของรูปย่อเอง เรียก `requestDisallowInterceptTouchEvent(true)` เมื่อการ์ดเปิด เพื่อไม่ให้ RecyclerView เลื่อนแข่ง

**แกลเลอรี: ค้นหา:**
- **เปิด:** แตะแว่นขยายแล้วช่องค้นหาค่อย ๆ ยืดจากปุ่มจนเต็มแถว (680ms EASE) ปุ่มกลับกับชื่อหน้าจางและเลื่อนออกไปทางซ้าย ช่องพิมพ์และปุ่ม "ยกเลิก" จางเข้าหลังจากนั้น 260ms คีย์บอร์ดขึ้นหลังช่องยืดเกือบเสร็จ (420ms) จะได้ไม่กระตุก
- **ผลค้นหา:** ค้นจากข้อความในภาพ (OCR ของงาน A) หมวด และชื่ออัลบั้ม หัวข้อตารางเปลี่ยนเป็น "ผลการค้นหา"

## 15. ข้อควรระวัง

- **ฟอนต์ 2.0 และ 7 โหมด:** ชื่อยาวอย่าง "ความละเอียดสูง" กว้างราว 116dp ที่ฟอนต์ 1.0 ถ้าขยายเป็น 2.0 แถบจะยาวกว่าจอมาก ซึ่งไม่ผิด เพราะแถบเลื่อนได้และโหมดที่เลือกอยู่กลางเสมอ แต่ห้ามตัดข้อความด้วย ellipsis ในแถบ ให้รอเกณฑ์จากงาน D
- **16:9 ซ้อนปุ่มบนภาพ:** ในต้นแบบ พรีวิว 16:9 ยาวลงไปใต้แถบโหมดและซูม ปุ่มจึงอยู่บนภาพ ชื่อโหมดที่ไม่ได้เลือกควรมีเงาข้อความบาง ๆ หรือพื้นกระจกจาง เพื่อให้อ่านออกบนฉากสว่าง ต้องวัดบน Reno15
- **ไม่ได้วัดประสิทธิภาพ:** ต้นแบบรันในเบราว์เซอร์ จึงไม่ได้บอกว่าบน Reno15 จะได้ 60/120 fps หรือไม่ ควรวัดเฟรมตกด้วย `adb shell dumpsys gfxinfo` ตอนเปลี่ยนโหมดและเปิดชีตก่อนและหลังแก้

## 16. ลำดับงานที่แนะนำสำหรับ Codex

1. ภาพค้างเบลอระหว่างผูกกล้องใหม่ตอนเปลี่ยนโหมดและสลับกล้อง (ข้อ 3) เพราะผู้ใช้รู้สึกกระตุกตรงนี้มากที่สุด
2. ไอคอน VectorDrawable + พื้นกระจกแบบไม่เบลอ (กระทบหลายไฟล์ แต่ความเสี่ยงต่ำ)
3. ค่าเวลาและ easing กลางใน `Ui.kt` แล้วใช้กับปุ่ม ชัตเตอร์ รูปย่อ และสลับกล้อง
4. แถบโหมดที่สร้างครั้งเดียวและเลื่อนให้โหมดที่เลือกอยู่กลาง (ข้อ 5) พร้อมแก้ลิสต์ปัดบนพรีวิว
5. `mode_bar` + ชีตปรับแต่งด้วยปุ่ม + และ −
6. การลาก และการเบลอจริงของชีตบน API 31 ขึ้นไป
7. แถบบนแบบแสดงสถานะ + แผงปัดขึ้น (ข้อ 7–8) ทำพร้อมกัน เพราะเมื่อเอาปุ่มออกจากแถบบนต้องมีที่ใหม่ให้ทันที
8. แถวชิปโปร (ข้อ 9)
9. หน้าตั้งค่าแบบเต็มหน้า (ข้อ 10)
10. แกลเลอรีทั้งเครื่องและหมวดในแอป (ข้อ 11) ทำทีหลังสุด เพราะต้องแก้ manifest ฐานข้อมูล และขอสิทธิ์ใหม่
11. ปรับแต่งภาพ (ข้อ 8) หลังตกลงเรื่องขอบเขตกับ Ogay แล้ว
12. กระจกเด้งตามนิ้ว และเมนูกระจกแบบเดียวกันทุกที่ (ข้อ 12) ทำพร้อมข้อ 2–3 ได้ เพราะเป็นส่วนกลางใน `Ui.kt`
13. วงล้อซูมและการล็อกที่เลนส์ (ข้อ 12) หลังวัดระยะเลนส์บน Reno15 แล้ว
14. แผงปรับค่าแบบเดียวสำหรับโปรและวิดีโอ แถบไล่สีที่มีหาง และวิดีโอโปรที่ปรับค่าวิดีโอได้ (ข้อ 12–13)
15. แถบความสว่างขอบซ้ายพร้อมล็อก AE และโฟกัสมือขอบขวา (ข้อ 13) ต้องทดสอบบน Reno15 ว่ากล้องเปิด manual focus ให้หรือไม่
16. เมนูลากเลือก (ข้อ 13) ทำพร้อมเมนูกระจกในข้อ 12
17. แถบโหมดลากต่อเนื่อง และปล่อยเอฟเฟกต์กระจกเมื่อเริ่มลาก (ข้อ 14) ควรทำพร้อมข้อ 4 เพราะแตะส่วนเดียวกัน
18. ล็อก AE/AF ด้วยการกดค้าง และแถบเลื่อนยืดหยุ่น (ข้อ 14)
19. แอนิเมชันหยดน้ำแบบชิ้นเดียว (ข้อ 14) ทำเป็นตัวช่วยกลางใน `Ui.kt` แล้วใช้กับแผง ชีต เมนู แผงปรับค่า ป้าย ภาพย่อเลนส์ และตัวดูรูป
20. กดค้างดูตัวอย่างและค้นหาในแกลเลอรี (ข้อ 14) พร้อมแกลเลอรีในข้อ 11
21. ภาพย่อเลนส์เมื่อซูมเกิน 10× (ข้อ 14) หลังรู้ `maxZoomRatio` จริงของ Reno15
