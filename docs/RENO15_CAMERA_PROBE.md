# ทดสอบกล้อง Reno15 แบบกดครั้งเดียว

รายงานจาก CPH2825 ที่ผู้ใช้ส่งมาแสดง AE ปกติสูงสุด 30 fps ทุก ID และ high-speed 720p/1080p 120/240 fps บน ID 0 กับ 2 ข้อมูลนี้ยังไม่ใช่ผลบันทึกจริง

## วิธีใช้

1. เปิดรายงานความสามารถกล้อง แล้วกด **ทดสอบกล้อง**
2. ค่าเริ่มต้นเลือก **กล้อง 0 · 1920x1080 · 120 fps → เล่น 30 fps** ถ้าเครื่องรายงานชุดนี้
3. หันกล้องไปยังวัตถุที่ขยับในฉากสว่าง แล้วกด **เริ่มทดสอบ 10 วินาที**
4. รอให้หยุดและตรวจคลิปอัตโนมัติ จากนั้นกด **บันทึกและส่งรายงาน** แนบไฟล์ `camera-probe-....json` ให้ตรวจ
5. หากต้องตรวจ 240 fps หรือ ID 2 ให้เลือกชุดนั้นแล้วทดสอบใหม่

หน้าทดสอบใช้ Camera2 โดยตรงและไม่มีเสียง ถ้าไม่มี high-speed จะใช้ชุดควบคุม 720p30 เมื่อมีให้เลือก ไม่มีการเปิด 60 fps ที่อุปกรณ์ไม่ได้ประกาศ

## รายงานเพิ่มอะไร

- schema 2 ของรายงานความสามารถ: min frame duration ของ MediaRecorder และ SurfaceTexture ที่ 720p/1080p/4K, high-speed ranges ทั้ง fixed/variable, CamcorderProfiles และ AVC/HEVC size/rate checks (ข้อมูล codec เป็นข้อมูลประกอบ ไม่ตัด high-speed ทิ้งด้วยเงื่อนไข codec เพียงอย่างเดียว)
- ผลทดสอบ: camera ID, size, capture FPS ที่ขอ, playback FPS ที่คาด, session type, orientation, stage/error, เวลาถ่ายจริง, sample/frame count, FPS ในไฟล์, sensor callbacks และค่าประมาณ frame count / เวลาถ่าย
- ค่าประมาณจากจำนวนเฟรมไม่ได้ตรวจว่าแต่ละเฟรมเป็นภาพที่แตกต่างจริง และ sensor callbacks อาจเป็น batch จึงรายงานแยกกัน
- คลิปและรายงานเก็บในแอป/คลัง Luma การแชร์เกิดจากผู้ใช้กดเท่านั้น การออกจากหน้าระหว่างอัดจะหยุดและระบุ cancelled

## เกณฑ์ตรวจ

- CI มีชุดควบคุม 30 fps: เริ่มจริง, หยุดเองหลัง 10 วินาที, ไฟล์ไม่ว่าง, ไม่มีเสียง และ JSON มีผลเฟรมจริง
- เพิ่มหน้าทดสอบเข้า accessibility audit ที่ฟอนต์ 1.0/2.0 โดยคงเกณฑ์เดิม
- Reno15 ต้องตรวจ 1080p120/240 จริง ไม่ใช้ผล emulator ยืนยัน high-speed
- 60 fps ปกติยังต้องอ่าน min frame duration และทดสอบชุด session ที่เหมาะสมเพิ่มเติม ห้ามใช้ theoretical max FPS เป็นผลสำเร็จ
